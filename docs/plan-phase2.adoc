= Phase 2: Agent-Native Interface (Weeks 5–6)

== Objective

Agents consume contracts efficiently; no protocol lock-in.

== Theme

Execution-based MCP returns compact results, making efficient local and small-context models viable where schema-loading MCP would overflow their windows.

== Deliverables

|===
|ID |Deliverable |Crate |Status |Acceptance Criteria

|2.1 |RocksDB graph persistence |`aden-graph` |Planned |<500ms incremental re-index for 10K-file repo; crash recovery test passes
|2.2 |`.adg` deterministic emitter |`aden-graph` |Planned |Same `.aden` → identical `.adg` bytes (SHA-256 match)
|2.3 |Tier 1 structural queries (BFS/DFS) |`aden-retrieval` |Planned |15/15 correctness on DKB benchmark suite
|2.4 |Tier 2 semantic layer (optional Jina/CodeBERT) |`aden-retrieval` |Planned |Falls back to Tier 1 if embeddings disabled
|2.5 |Tier 3 lexical search (tantivy) |`aden-retrieval` |Planned |<50ms symbol name search
|2.6 |`.adq` interpreter (Rhai-based, sandboxed) |`aden-retrieval` |Planned |Supports `node()`, `incoming()`, `outgoing()`, `where`; no FS write or network access
|2.7 |Execution-based MCP server |`aden-mcp` |Planned |Loads <50ms; exposes `aden_query` tool only; minimal token footprint vs. schema-loading
|2.8 |Google A2A agent bridge |`aden-a2a` |Planned |Wraps `.adq` execution as A2A capability descriptor
|2.9 |`aden-asm --format=adg` |`aden-core` |Planned |LLM context defaults to compact `.adg`; `--format=aden` for human-rich prose
|===

== Exit Gate

Cursor queries Aden via MCP with 200-token `.adq` script; receives bounded `.adg` result in <200ms.
