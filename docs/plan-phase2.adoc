= Phase 2: Delivering Overlay Intent (and making it ergonomic)

== Objective

Phase 1 (<<plan-phase1>>) made `gen` non-destructive and gave durable
human/agent intent a home (`.aden/overlays/<anchor>.adoc`), protecting it from
being clobbered. But that intent is currently *inert*: no reader
(`asm`/`ask`/`query`/`check`) ever surfaces it, and authoring an overlay means
hand-creating a file at a sanitized path with an exact tag. Phase 2 makes the
intent actually reach consumers and makes it pleasant to author.

== The central decision: delivery enables "notify", not "block"

Phase 1 conflict semantics *block*: a guarded symbol whose generated content
changed is held at its old stored doc until the human resolves. That is the
correct *safe* default only while intent is undelivered — blocking at least
keeps something observable.

Once intent is delivered to readers, the better model is *notify*:

* The store always tracks source (generated content updates freely — no drift).
* Overlay intent is always preserved (separate file) and always delivered to
  readers (folded into the assembled view).
* A guarded generated unit that changes raises a *notice* (proposal) so the
  human re-reviews their note — it does not withhold the update.

`notify` keeps the graph fresh, removes the `--force-regen` friction, and is
softer / more LLM-guided. *It must land together with delivery* — shipping
`notify` without delivery would make overlays do nothing observable.

== Delivery design: fold at graph-build, keep the store pure

The store stays *pure generated* — this is what `reconcile_anchor` reads as its
clean `base`, so it must not contain overlay content. Instead, fold overlay
durable blocks into the *in-memory* graph when it is built from the store:

* `AdenGraph::build_from_storage(storage, root)` — for each loaded
  `DocumentNode`, look up its overlay and append the durable
  (`[human]`/`[agent]`/…) blocks to the node's blocks.
* Every reader (`asm`, `query`, `ask`, `check`) builds the graph through this one
  chokepoint, so all of them gain overlay-awareness uniformly with no per-reader
  changes.
* The overlay file remains the git-tracked source of truth; the store is the
  rebuildable pure-generated layer; the graph is the merged read view.

This requires moving the overlay helpers (`overlay_path`,
`sanitize_anchor_filename`, `load_overlay`, `overlay_slugs`) from
`aden-cli::commands::overlay` into `aden-core` (their proper home; both
`aden-graph` and `aden-cli` then depend on them). `aden-cli` keeps a re-export
for compatibility.

== Out of scope (Phase 3+)

`[constitution]` precedence in conflict resolution; 1.5 region-aware `heal`
scan (`OverlayConflict` drift class) — folded here as a lower-priority detection
nicety since the gen gate already closes the clobber risk.
