= Aden Architecture

== The Big Picture

Aden is a **referential context compiler** — it transforms codebases into traversable knowledge graphs. The goal is making the *structure of understanding* explicit, machine-readable, and queryable by both humans and AI agents.

[ditaa, aden-pipeline, png]
----

                      +-----------+    +-----------+
                      |  .adoc    |    | aden ask  |

                      +-----------+    +-----------+
----

== Core Concepts

=== The Graph

Every document, function, module, and decision becomes a **node**. Every relationship — imports, calls, constraints, justifications — becomes a **typed edge**.

[source]
----
[[auth-module]]
= auth module

== Functions

* login() -- calls --> validate()
* validate() -- uses --> crypto()
* logout() -- calls --> session::clear()
----

Typed edges enforce referential integrity. Open strings are rejected.

=== The Contract

A contract is an AsciiDoc (`.adoc`) or Aden (`.aden`) file that describes a piece of the system. Contracts are **deterministically generated** from source code — the same source always produces the same contract.

[source]
----
[[module-aden-core]]
= module::aden-core

|===
|Type |Kind |Description
|Document |struct |Root node in the graph
|Block |enum |Content block types
|===
----

=== Region Semantics

Contracts support regions that determine how content is handled during regeneration:

|===
|Region |Purpose |Preserved on Regen?

|[generated] |Auto-extracted from source |No — overwritten

|[human] |Architectural notes, decisions |Yes

|[agent] |AI agent observations |Yes

|[security] |Security requirements |Yes

|[constitution] |Governance directives |Yes

|[override] |CI override authority |Yes
|===

=== Token Budgeting

AI agents have finite context windows. Aden budgets tokens by:

1. **BFS traversal** — walk the graph from a starting node
2. **Depth limiting** — stop at depth N (default: 2)
3. **Token estimation** — ~4/3 bytes per token heuristic
4. **Assembly** — concatenate documents until budget exhausted

=== 1. Parse (aden-parse)

Extracts symbols, signatures, and relationships from source code using tree-sitter.

|===
|Language |Depth |Analysis

|Rust |Deep |Full AST, trait bounds, lifetimes

|Python |Deep |Import-aware, decorators

|Go |Deep |Full AST, interfaces

|TypeScript/JS |Deep |Full AST, generics

|305+ others |Shallow |Generic AST fallback
|===

Discovery is **language-agnostic**: `aden gen --auto` walks the whole project and
keeps every file whose extension a parser can handle (the canonical set is
`aden_parse::supported_extensions()`), honoring `.adenignore`. It does *not* gate
on the build manifest, so a polyglot repo — or a Rust repo with Python scripts and
Markdown docs — is fully covered rather than reduced to a single language.

Grammars are compiled into the binary at build time via `TSLP_LANGUAGES` (set in
`.cargo/config.toml`); the language pack would otherwise download them at runtime,
which breaks offline and air-gapped use. See CONTRIBUTING.md.

=== 2. Graph Build (aden-graph)

Builds a directed graph (`DiGraph`) from all contracts + documentation + <<adr-001>> + <<plan-phase0>> + <<project-context>>.

- Nodes: anchors (`[[name]]`)
- Edges: typed relationships (`Uses`, `Calls`, `Constrains`, `Documents`, etc.)
- Validation: cycle detection, orphan detection, reference resolution

=== 3. Validate (aden check)

Ensures referential integrity:

- Every `<<anchor>>` resolves to a real `[[anchor]]`
- No duplicate anchors
- No include cycles
- Source hash integrity

=== 4. Assemble (aden-asm / aden-ask)

Given a starting anchor and token budget:

1. BFS traversal from anchor
2. Collect documents along selected edge types
3. Estimate token count per document
4. Stop when budget exhausted
5. Concatenate with `<<<` page breaks

== Key Features

=== Self-Healing Contracts

When source code changes, contracts become stale. `aden heal` detects drift:

|===
|Event |Meaning |Fix

|StaleHash |Source changed, contract not regenerated |`aden gen --merge`

|MissingContract |No contract for source file |`aden gen`

|SignatureMismatch |Function signature changed |`aden heal --fix`

|OrphanAnchor |Contract has no incoming edges |Add `<<ref>>` or delete
|===

=== Three-Way Merge

`aden gen --merge` performs a three-way merge:

- **ground**: freshly parsed AST
- **base**: last generated contract
- **working**: current file with human edits

Output: per-block `MergeAction`:

- `UpdateGenerated` — overwrite with new AST
- `PreserveHuman` — keep human blocks intact
- `Conflict` — cannot auto-merge, needs review
- `InsertGenerated` — new symbols detected
- `DeleteGenerated` — symbols removed from source

=== Constitutional Governance

The `[constitution]` block declares governance rules:

[source]
----
[constitution]
.agents = [claude, cursor]
.precedence = ai-overrides

[role=security]
===
The security agent has final authority on any code
touching authentication or authorization.
===
----

`aden check` resolves conflicts using stated precedence.

=== Tagged Includes

Conditional content via AsciiDoc tags:

[source]
----
// tag::main[]
pub fn main() {
    setup();
    run();
}
// end::main[]

// tag::admin[]
pub fn admin_panel() { ... }
// end::admin[]
----

Filter at build time:
```bash
aden asm --include-tag main
aden asm --exclude-tag admin
```

=== Checklist Tracking

Progress tracked in contracts:

[source]
----
[checklist]
* [x] Phase 0 complete
* [ ] Phase 1 in progress
* [ ] Phase 2 planned
----

=== Rich Metadata

Document-level metadata:

[source]
----
:author: RioPlay
:version: 1.0.0
:date: 2026-05-25
:license: AGPL-3.0
----

Extracted and indexed for search.

== Security Posture

- `contracts/` and `.aden/` are build artifacts — auto-ignored in `.gitignore`
- Include directives bounded to project root — no path traversal
- No `unsafe` blocks in application code
- AGPL-3.0-or-later license prevents cloud capture without sharing modifications
