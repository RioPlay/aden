= ADR-005: Brain-Like Semantic Networks in Aden

== Status

Accepted (2026-05-26)

== Context

Aden's current graph model captures code relationships (Uses, Implements, Tests, Calls, etc.) but lacks:

1. **Semantic association types** — no way to express "related to", "is a", "part of"
2. **Spreading activation** — queries are exact-match or BM25 keyword-based, not associative
3. **Conceptual hierarchy** — no inheritance/subsumption for knowledge organization
4. **Plain-text concept linking** — no standard way for humans to define relationships in `.adoc` files

This ADR proposes adding brain-like semantic networks to Aden.

== Decision

We will extend Aden with:

1. **Semantic Edge Types** — new edge types for conceptual relationships
2. **Spreading Activation Search** — associative query traversal with activation spread
3. **Concept Declaration Syntax** — standard AsciiDoc macros for defining semantic links
4. **Neural Token Budgeting** — context assembly based on semantic proximity

=== 1. Semantic Edge Types

Extend `EdgeType` with brain-inspired semantic relationships:

| Edge Type | Brain Analog | Description |
|-----------|--------------|--------------|
| `RelatesTo` | Synaptic association | General relatedness (bidirectional feel) |
| `IsA` | Category membership | Inheritance/subsumption (dog IS A animal) |
| `PartOf` | Structural composition | Component relationship (wheel PART_OF car) |
| `SimilarTo` | Pattern matching | Analogical relationship |
| `Causes` | Causal chain | Direct causation |
| `Implies` | Logical entailment | Inference relationship |
| `SynonymOf` | Lexical redundancy | Alternate naming |
| `AntonymOf` | Contrast activation | Opposite concepts |
| `AssociatedWith` | Hebbian co-activation | Frequently co-occur concepts |
| `PrerequisiteFor` | Learning sequence | Must-know before |
| `Explains` | Explanatory hierarchy | Provides explanation for |

=== 2. Spreading Activation Algorithm

Implement semantic search modeled on neural spreading activation:

[source,rust]
----
struct SemanticSearch {
    /// Initial activation per matching concept
    initial_activation: f64,
    /// Decay factor per hop (0.0-1.0)
    decay_rate: f64,
    /// Maximum traversal depth
    max_depth: usize,
    /// Activation threshold to include in results
    threshold: f64,
}

impl SemanticSearch {
    /// Execute spreading activation search from query terms.
    pub fn search(&self, graph: &AdenGraph, query: &[String]) -> Vec<ScoredAnchor> {
        // Phase 1: Seed - activate nodes matching query terms
        let mut activations: HashMap<NodeIndex, f64> = HashMap::new();
        for term in query {
            for (idx, node) in graph.all_nodes() {
                if node.anchor.contains(term) || node.content.contains(term) {
                    activations.insert(idx, self.initial_activation);
                }
            }
        }

        // Phase 2: Spread - iteratively propagate activation
        for _depth in 0..self.max_depth {
            let mut new_activations = activations.clone();
            for (idx, current_activation) in &activations {
                if *current_activation < self.threshold {
                    continue;
                }
                // Spread to neighbors
                for neighbor in graph.neighbors(*idx) {
                    let edge_weight = self.edge_weight(graph.get_edge(idx, neighbor));
                    let spread = current_activation * self.decay_rate * edge_weight;
                    *new_activations.entry(neighbor).or_insert(0.0) += spread;
                }
            }
            activations = new_activations;
        }

        // Phase 3: Collect results above threshold
        activations
            .into_iter()
            .filter(|(_, score)| *score >= self.threshold)
            .map(|(idx, score)| (graph.get_anchor(idx), score))
            .collect()
    }

    fn edge_weight(&self, edge_type: EdgeType) -> f64 {
        match edge_type {
            // Strong associations
            EdgeType::IsA => 1.0,
            EdgeType::PartOf => 0.9,
            EdgeType::Causes => 0.9,
            // Medium associations
            EdgeType::SimilarTo => 0.7,
            EdgeType::PrerequisiteFor => 0.7,
            EdgeType::Implies => 0.7,
            // Weak associations
            EdgeType::RelatesTo => 0.5,
            EdgeType::AssociatedWith => 0.5,
            EdgeType::Explains => 0.5,
            // Code relationships (strong in domain)
            EdgeType::Uses => 0.8,
            EdgeType::Calls => 0.8,
            _ => 0.3,
        }
    }
}
----

=== 3. Concept Declaration Syntax

Standard AsciiDoc macros for defining semantic relationships in `.adoc` files:

[source,adoc]
----
// Direct semantic links using inline macros
// Example: See &lt;&lt;concept-noun, Noun&gt;&gt; for the definition of nouns.
// Example: This concept is &lt;&lt;is-a&gt;&gt; related to &lt;&lt;linguistics&gt;&gt;.
// Example: The brain &lt;&lt;part-of&gt;&gt; nervous system.

// Explicit semantic block
[semantics]
----
# Hierarchical relationships
Noun IsA PartOfSpeech
Verb IsA PartOfSpeech
Adjective IsA PartOfSpeech

# Associations
Pronoun RelatedTo Noun
Preposition RelatedTo Grammar

# Learning sequence
Noun PrerequisiteFor Verb
----

[source,adoc]
----
// Bidirectional association (creates two edges)
// Example: This idea is &lt;&lt;-&gt;&gt; associated with &lt;&lt;that-concept&gt;&gt;.

// Similarity assertion
// Example: His approach is &lt;&lt;~&gt;&gt; similar to &lt;&lt;other-approach&gt;&gt;.
----

=== 4. Neural Token Budgeting

Extend `aden-asm` to assemble context based on semantic proximity:

[source,rust]
----
struct NeuralBudget {
    /// Total token budget
    budget: usize,
    /// Direct hits allocation (percentage)
    direct_allocation: f64,
    /// Semantic spread allocation
    spread_allocation: f64,
}

impl NeuralBudget {
    pub fn assemble(&self, graph: &AdenGraph, query: &[String]) -> Context {
        let search = SemanticSearch::default();
        let results = search.search(graph, query);

        // Split: direct matches vs spread activations
        let direct: Vec<_> = results.iter().filter(|r| r.is_direct).collect();
        let spread: Vec<_> = results.iter().filter(|r| !r.is_direct).collect();

        let direct_budget = (self.budget as f64 * self.direct_allocation) as usize;
        let spread_budget = self.budget - direct_budget;

        // Assemble from direct hits first
        let mut context = self.assemble_group(graph, &direct, direct_budget);

        // Then fill from semantic spread if budget remains
        if context.tokens_remaining() > 100 {
            let spread_ctx = self.assemble_group(graph, &spread, spread_budget);
            context.merge(spread_ctx);
        }

        context
    }
}
----

== Consequences

=== Positive

1. **Semantic search** — users can discover related concepts even without exact keyword matches
2. **Knowledge organization** — explicit hierarchical relationships enable better categorization
3. **Learning paths** — prerequisite relationships enable intelligent curriculum generation
4. **Analogical reasoning** — similarity edges enable cross-domain knowledge transfer
5. **Human-authored semantics** — architects can encode domain expertise as explicit relationships

=== Negative

1. **Graph complexity** — more edge types means more validation complexity
2. **Performance** — spreading activation is O(n * depth) vs O(1) for indexed lookup
3. **Maintenance burden** — semantic relationships must be kept in sync with code
4. **Ambiguity** — human-defined semantics may be subjective

=== Neutral

1. **Migration path** — existing graphs continue to work; new features opt-in
2. **Backwards compatibility** — current EdgeTypes preserved; new ones additive

== Open Questions

1. **Bidirectional edges** — Should `A RelatesTo B` automatically create `B RelatesTo A`?
2. **Edge weight customization** — Allow authors to specify custom weights?
3. **Temporal decay** — Should recent associations score higher?
4. **Cross-graph semantics** — Support semantic links between separate `.adoc` files in different directories?
