[[release-binaries]]
= Releasing Aden binaries

Aden publishes self-contained, source-free bundles. Each bundle contains both
`aden` and `aden-mcp`, a platform-local installer, `README.md`, `LICENSE`,
`NOTICE.md`, a manifest, and binary checksums. Unix releases are `.tar.gz`;
Windows releases are `.zip`.

== Supported bundles

* Linux GNU: x86_64 and ARM64
* macOS: Intel and Apple Silicon
* Windows MSVC: x86_64

The default release excludes dense search and the standalone LSP. Those remain
separately buildable features and are not implied by a standard binary bundle.

== User installation

. Download the archive for the host target and the adjacent `.sha256` file.
. Verify the archive against that checksum (or the release-wide `SHA256SUMS`).
. Extract the archive and enter its top-level directory.
. Run `./install.sh` on Linux/macOS or `.\install.ps1` in PowerShell.

The bundled installers copy the adjacent prebuilt executables; they never invoke
Cargo and never edit PATH, shell profiles, MCP configuration, or project files.
Existing binaries require `--force` / `-Force` before replacement.

== Maintainer workflow

The authoritative workflow is `.github/workflows/release.yml`.

. Update the workspace version and `Cargo.lock`.
. Move the relevant changelog entries under an exact `## [X.Y.Z]` heading.
. Merge the release commit to `main` and ensure ordinary CI is green.
. Run the Manual Quality workflow for that exact commit and verify it succeeds.
  The Release workflow requires this verdict even for a manual dry run.
. Run the Release workflow manually from that same commit with version `X.Y.Z`.
  The dry run validates an exact SemVer, workspace-version, and changelog-heading
  match before it builds, packages, attests, downloads, installs, and smokes all
  target bundles without publishing a GitHub Release.
. Create and push annotated tag `vX.Y.Z` at the reviewed commit.
. The tag workflow repeats the release gate and creates a *draft* GitHub Release.
. Review generated notes, bundle list, `SHA256SUMS`, and attestations, then publish
  the draft manually.

Tag validation rejects non-SemVer names, versions that differ from Cargo metadata,
missing changelog headings, and published tag commits that are not on `main`.

== Local bundle test

[source,bash]
----
host="$(rustc -vV | sed -n 's/^host: //p')"
version="$(cargo metadata --locked --no-deps --format-version 1 | jq -r '.packages[] | select(.name == "aden") | .version')"
case "$host" in *windows*) archive_ext=zip ;; *) archive_ext=tar.gz ;; esac
cargo build --locked --release --target "$host" -p aden-cli -p aden-mcp
scripts/package-release.sh "$host" "$version" dist
scripts/test-release-bundle.sh "dist/aden-v$version-$host.$archive_ext" "$host" "$version"
----

`scripts/test-release-bundle.sh` uses fixture executables to prove deterministic
archives, checksum validation, overwrite refusal, forced update, and uninstall.
Passing an archive, target, and version validates a real bundle without executing
foreign-target binaries.

== Trust and rollback

The workflow produces SHA-256 checksums and GitHub build-provenance attestations.
Long-lived signing keys are deliberately deferred until a human key-custody and
recovery owner exists. Releases remain drafts until a maintainer reviews them.
Rollback means reinstalling the previous verified bundle; Aden's graph stores are
rebuildable and are not removed by bundle uninstallers.
