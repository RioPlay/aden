== Core Commands

=== init

Scaffold `.agent/` templates in a target repository.

[source,bash]
----
aden init [DIR]
aden init . --with-secure-refs
----

Creates:
- `.agent/` — templates, onboarding docs, constraints, session log
- `.adenignore` — security-first defaults (skips `*.env`, `*.key`, `target/`)

|===
|Flag |Description

|--with-secure-refs |Scaffolds CWE Top 25 / OWASP SCP reference stubs under `.agent/secure-coding-refs/`
|--agents-md |Also seed a short, append-only aden usage block into the repo-root `AGENTS.md` (ADR-004). Idempotent; only ever touches its own marked block
|===

=== agents-md

Seed or refresh the append-only aden usage block in a repo-root `AGENTS.md`,
without the full `init` scaffolding (ADR-004). Use this when a repo already has
an `AGENTS.md` and you just want AI agents to use aden by default. Idempotent:
it only ever touches its own marked block, so hand-written content around it is
preserved. Remove the block to opt out.

[source,bash]
----
aden agents-md [DIR]
----

=== new

Create a new project from a language template with Aden scaffolding.

[source,bash]
----
aden new NAME --lang rust|go|js [DIR]
----

Scaffolds:
- `Cargo.toml` and a starter `src/main.rs` (for the Rust template)
- `.agent/` with templates and constraints
- `.adenignore` with security defaults
- `.aden/docs/README.adoc` with project identity and quick-start steps

=== gen

Compile source into the knowledge graph. Store-first: `gen` writes only to the
per-user project store (run `aden store path` to see its location; see ADR-003)
and emits no files. A directory indexes the whole project; a single file
re-indexes just that file.

[source,bash]
----
# Single file (re-index just this file)
aden gen src/lib.rs

# Polyglot: works identically for any language
aden gen src/app.py
aden gen cmd/main.go

# Whole project (a directory is auto-discovered)
aden gen .

# Quiet mode for CI (summary only)
aden gen . --quiet
----

|===
|Flag |Description

|--auto |Auto-discover source files for the whole project (default when PATH is a directory)
|--quiet |Suppress per-file output (summary only)
|--propose |Dry-run: reconcile and write conflict proposals without changing the store
|--force-regen |Bypass the merge gate and overwrite the store (may clobber `[human]`/`[agent]` overlay collisions)
|===

`gen` reconciles any `[human]`/`[agent]` overlays (see `aden overlay`) as the
`working` layer of a three-way merge, so regeneration never clobbers durable
intent. `--propose` writes review proposals for conflicts instead of mutating the
store; `--force-regen` skips that merge gate entirely.

=== regen

Recompile the whole project into the knowledge graph from scratch. This is the
full-rebuild counterpart to the incremental `aden gen .` — *not* a transparent
alias: it clears `gen-cache.json` and the graph cache first, then regenerates,
always re-storing all symbols (use after a big merge or when caches may be
stale).

[source,bash]
----
aden regen
aden regen .
----

=== check

Verify all `<<refs>>` resolve to existing `[[anchors]]`.

[source,bash]
----
aden check [DIR]
aden check . --severity Forbid
----

Validates:
- Every cross-reference resolves
- No include cycles
- No duplicate anchors
- Source hash integrity (a doc describing code that has changed is flagged stale)
- Typed edges valid (a doc referencing a moved/renamed symbol — whose `aden://`
  anchor no longer exists — is flagged as a broken reference)
- *Documentation path links* — markdown `[text](path)` and adoc
  `xref:`/`link:`/`include::` whose repo-relative target file no longer exists
  (moved or renamed). Illustrative backtick mentions and fenced code blocks are
  not checked; a line bearing `aden:allow-path` is exempt.

|===
|Severity |Behavior

|Suggest |Non-blocking recommendation
|Warn |Surfaces in output
|Forbid |Fails CI gate
|===

This is the documentation-accuracy gate: CI runs `aden check . --severity Forbid`
(and it is part of `ci-check` / the pre-push hook), so a doc that drifts from the
code — a stale signature, a reference to a relocated symbol, or a link to a moved
file — fails the build. `--json` emits `{ok, errors, warnings, info}`.

=== lint

Lint source files with fast, language-aware heuristic checks (per-line pattern
rules; comment lines are skipped). Not a full type-aware analyzer — for deep
correctness use the language's own toolchain.

[source,bash]
----
aden lint [PATH]
aden lint . --fix              # apply safe auto-fixes (e.g. redundant conversions)
aden lint . --severity Error
aden lint . --json             # machine-readable; banner suppressed
aden lint . --dead-code        # flag symbols with no incoming graph edges
aden lint . --dead-code --include-public  # also flag public API / entry points
----

Checks (language-dependent):
- Security patterns: `eval`/`exec` use, etc.
- Risky constructs: `unsafe fn`, `unwrap()`, `todo!()`/`unimplemented!()`
- Leftover debug prints (including C# `Console.Write*`)
- Redundant chained conversions (`.to_string().to_string()`)
- Rust: unnecessary `.clone()` on `Copy` types, `unwrap_or_else(|| <Default>)`
  that should be `unwrap_or_default()`
- Python: shadowing a built-in name (`list`/`dict`/`str`/`int`/`type`)
- TypeScript: `any` type annotations, loose equality (`==`/`!=` vs `===`/`!==`)
- C#: empty `catch {}` blocks
- AsciiDoc/`.aden`: ASCII-art graphs that should be Mermaid

Code-level rules are matched against the line with string literals and comments
blanked out, and type-name/keyword rules require a whole-word match — so a
pattern quoted in a string (`"a == b"`), mentioned in a comment, or appearing
as a substring of an identifier (`parse_i32`, `getAnyResult`) no longer
false-fires. The Mermaid exclusion for the ASCII-graph rule is stateful, so a
multi-line `[mermaid]` fenced block is never flagged.

`--fix` applies only the unambiguously-safe rewrites and reports how many issues
still need manual review.

`--dead-code` loads the knowledge graph and flags `Function`/`Type` nodes with
zero incoming edges (callers/references). Conservative by default: entry points
(`main`), metadata anchors, and synthetic `mod-` nodes are skipped.
`--include-public` widens scope to public API symbols. Findings merge into the
normal output so `--severity` and `--json` apply automatically.

=== test

Discover and run tests across all languages.

[source,bash]
----
aden test [PATH]
aden test . --scope unit
aden test . --scope integration
aden test . --scope all
aden test . --filter PATTERN
aden test . --list
----

Supports:
- Rust: `#[test]`, `#[cfg(test)]`
- Python: `def test_*()`, `class Test*`
- Go: `func Test*`
- TypeScript: `describe/it/test`, `@Test`
- Java: `@Test`, `@ParameterizedTest`
- ~113 further languages via the generic tree-sitter extractor (305+ grammars bundled; add entries to `ext_to_language_pack_id` in `router.rs` to expose more)

== Graph Commands

=== asm

Assemble a context prompt from the knowledge graph.

[source,bash]
----
# Basic usage
aden asm --from mod-aden-core

# With depth and budget
aden asm --from mod-aden-core --depth 3 --budget 8192

# Specific edge types
aden asm --from mod-aden-core --edge-types Uses,Calls

# Output to file
aden asm --from mod-aden-core --out context.adoc

# Silent mode (skip intro)
aden asm --from mod-aden-core --silent

# Inspect mode (show what would be included)
aden asm --from mod-aden-core --inspect

# Auto mode (adjust budget based on relevance)
aden asm --from mod-aden-core --auto

# Strict mode (never exceed budget)
aden asm --from mod-aden-core --strict

# Tag filtering
aden asm --from mod-aden-core --include-tag main
aden asm --from mod-aden-core --exclude-tag admin

# Set attributes for conditional processing
aden asm --from mod-aden-core --set-attr mode=production
----

|===
|Flag |Description |Default

|--from |Starting anchor (required) |—
|--depth |BFS traversal depth |2
|--budget |Token budget (bytes/4 heuristic) |8192
|--edge-types |Comma-separated edge types |All
|--out |Output file path |stdout
|--format |Output format: `llm` (default), `adg`, `aden` |llm
|--silent |Skip intro, output only context |false
|--auto |Adjust budget based on relevance |false
|--strict |Never exceed budget |false
|--inspect |Show what would be included |false
|--include-tag |Include content with this tag |—
|--exclude-tag |Exclude content with this tag |—
|--set-attr |Set attribute for conditional processing |—
|===

=== query

Query the knowledge graph and emit JSON.

[source,bash]
----
# Reachable nodes
aden query --from mod-aden-core --depth 2

# Backlinks (everything referencing this anchor)
aden query --backlinks mod-aden-core

# Impact analysis (transitive closure)
aden query --impact mod-aden-core

# JSON output
aden query --from mod-aden-core --json

# Table output
aden query --from mod-aden-core --format table
----

|===
|Flag |Description

|--from |Starting anchor
|--depth |BFS traversal depth
|--backlinks |Find all documents referencing this anchor
|--impact |Find transitive closure over dependency edges
|--edge-type |Restrict traversal to a single edge type (e.g. `Uses`, `Calls`)
|--format |Output format: `json` (default), `table`
|===

`--edge-type` is honored by all three modes (`--from`, `--backlinks`,
`--impact`). Because the graph is a multigraph, a single (source → target) pair
may carry several parallel edges of different types; a neighbor is kept when
*any* edge between the pair matches the filter.

`--backlinks` returns every node with an incoming edge to the anchor (all direct
referencers, regardless of edge type); narrow it to one relationship with
`--edge-type`. `--impact` traverses downstream dependency edges (`Uses`, `Calls`,
`Implements`, `Mutates`).

=== ask

Natural-language question to subgraph assembly.

[source,bash]
----
# Basic question
aden ask "How does authentication work?"

# Pin starting anchor
aden ask "How does authentication work?" --from mod-auth

# --budget is the BASE the relevance boost scales from (not a hard cap)
aden ask "What breaks if I rename this?" --budget 8192

# Exact budget, no boost — deterministic size for scripts/agents
aden ask "List the public API" --budget 4096 --strict

# Override the auto-classified intent / depth / edge types
aden ask "Explain the parser" --intent impact
aden ask "Explain the parser" --depth 4
aden ask "Explain the parser" --edge-types "Calls,Uses"

# Custom model
aden ask "Explain the parser" --model ollama:llama3

# Routing transparency: top candidates, scores, tiebreak, intent, fallback
aden ask "How does the parser work?" --explain
----

|===
|Flag |Description |Default

|--from |Pin starting anchor |—
|--budget |Base budget in bytes (boosted by relevance unless --strict) |4096
|--strict |Use --budget as an exact cap; no boost |false
|--intent |Override intent classification (`debug`, `usage`, `explain`, `refactor`, `impact`, `list`, `compare`, `count`, `general`) |auto
|--depth |Override BFS traversal depth |intent-driven
|--edge-types |Override edge types (comma-separated) |intent-driven
|--model |Custom LLM model string (e.g. `ollama:llama3`) |—
|--explain |Print routing transparency: top candidates with scores, the tiebreak decision, intent, overview signal, and any fallback swap |false
|===

NOTE: When built with the `dense` feature, `ask`'s anchor routing uses hybrid
(BM25 + dense embedding) retrieval — see the note under xref:commands.adoc#_search[search].
A question that resolves to a thin stub broadens to the resolved symbol's
*functional community* (see xref:commands.adoc#_communities[communities]) rather
than the whole project root.

Internally:
1. Search the index (BM25, or hybrid BM25+dense when the `dense` feature is built)
2. Classify intent by keyword/phrase scoring (highest-scoring intent wins):
   Explain, Usage, Refactor, Impact, Debug, List, Compare, Count, General
3. Select edge types and depth from the intent — override with
   `--intent` / `--depth` / `--edge-types`
4. BFS traversal from the matched anchor(s), ordering the frontier by query
   relevance (relevant neighbors first) and pruning near-duplicate neighbors via
   MMR (token-Jaccard, τ=0.8) so a tight budget is spent on distinct context
5. Token budgeting with a ~4-bytes-per-token heuristic. Unlike `asm` (a hard
   cap), `ask` *boosts* the budget by match relevance by default (up to ~4x,
   capped at 32k), treating `--budget` as a base; pass `--strict` to use
   `--budget` as an exact cap instead.
6. Assemble context with AsciiDoc markup stripped

|===
|Intent |Depth |Edge Types (primary; all also add the semantic edges)

|Explain |2 |Uses, Calls, Implements, Documents, Demonstrates
|Usage |2 |Uses, Requires, Documents, Demonstrates
|Refactor |4 |Calls, Uses, Mutates, Supersedes, Amends
|Impact |3 |Uses, Calls
|Debug |3 |Documents, Calls, Requires
|List |2 |Uses, Documents
|Compare |3 |Uses, Documents
|Count |1 |Documents, Uses
|General |2 |Uses, Documents
|===

In addition to the per-intent types above, every intent always traverses `Calls`
(the call graph stays navigable for all questions), and any intent that includes
`Documents` also traverses `Contains` (module→member containment).

NOTE: Classification is keyword/phrase based, so phrasing matters — e.g. "blast
radius of X" and "what depends on X" route to Impact, while an unusual phrasing
may fall back to a more general intent. Use `--intent` to pin it. All intents
also include the semantic edges `IsA`, `RelatesTo`, `SimilarTo`,
`AssociatedWith`, `Explains`.

=== search

Full-text search across the knowledge graph.

[source,bash]
----
aden search "authentication"
aden search "token budget" --limit 20
aden search "parser" --doc-type module
aden search "security" --semantics
aden search "token budget" --json    # structured envelope
----

|===
|Flag |Description |Default

|--limit |Max results |50
|--offset |Pagination offset |0
|--doc-type |Filter: module, adr, plan, use-case |All
|--semantics |Include semantic relationship results |false
|--json |Structured envelope instead of the human table |false
|===

With `--json` (or the global `-j`), `search` emits an envelope carrying explicit
counts and pagination so a caller never has to parse the table or guess whether
more results exist: `{total, returned, offset, truncated, results: [{anchor,
score, snippet}], semantic: [...]}`.

[NOTE]
====
*Hybrid (dense) retrieval — optional.* By default `search` and `ask` rank with
BM25 (lexical). Built with the `dense` cargo feature (`./install.sh --dense`),
they additionally run a local semantic-embedding search and fuse it with BM25 via
*Reciprocal Rank Fusion* — better natural-language matching while staying fully
offline and deterministic (pure-Rust `tract` ONNX runtime + the MIT-licensed
BAAI/bge-small-en-v1.5 model, fetched once via `scripts/fetch-bge-model.sh`).
Without the feature, retrieval is pure BM25. See xref:getting-started.adoc[Getting
Started] for setup. (`--semantics` is *unrelated* — it expands results along the
knowledge-graph edges, not via embeddings.)
====

=== grep

Structure-aware content search. Unlike plain `grep`, every match is tagged with
the symbol it lives inside, resolved from the knowledge graph — so a hit doubles
as a graph entry point you can feed straight into `aden asm --from <symbol>`.

[source,bash]
----
# Literal search (default), each hit tagged with its enclosing symbol
aden grep "InitDefaultHelpFlag"

# Regex search
aden grep --regex "\.parse\("

# Case-insensitive
aden grep -i "todo"

# Only matches that fall inside a known symbol
aden grep "buffer" --symbol-only

# Structured output
aden grep "parse" --json
----

|===
|Flag |Description |Default

|--regex |Treat PATTERN as a regular expression |false (literal)
|-i, --ignore-case |Case-insensitive match |false
|--symbol-only |Only report matches inside a known symbol |false
|--limit |Max results |100
|--json |Structured envelope (see below) |false
|===

Output is `file:line  (enclosing-symbol): matched text`. The enclosing symbol
resolves with bare-name lookup, so `aden asm --from <symbol>` expands it.

With `--json` (or the global `-j`), `grep` emits an envelope rather than a bare
array — `{total, returned, truncated, matches: [{file, line, symbol, anchor,
text}]}` — so a program reads the total and truncation state as data instead of
the human "... and N more" footer.

=== communities

Detect *functional communities* — clusters of symbols that call/use/reference
each other densely — from the knowledge graph, independent of the directory
layout. Useful for orienting in an unfamiliar codebase and as `ask` routing
targets. Language-agnostic (operates on the graph aden builds for any language).

[source,bash]
----
aden communities                      # clusters in the current project
aden communities --min-size 5         # hide small clusters (default min 2)
aden communities --resolution 2.5     # finer, smaller clusters (default 1.0)
aden communities --limit 10 --json    # cap output; machine-readable
----

|===
|Flag |Description |Default

|--min-size |Only show communities with at least N members |2
|--limit |Max communities shown |30
|--resolution |Granularity (>1.0 = more, smaller clusters) |1.0
|--json |Structured output instead of the human list |false
|===

Algorithm: deterministic multi-level modularity optimization (Louvain). Also
available as the MCP `communities` tool.

=== viz

Export a slice of the knowledge graph as a *text diagram* — Mermaid, Graphviz DOT,
an asciidoctor-diagram block, or JSON — for docs, PR comments, or CI. aden emits the
diagram *source* and never bundles a renderer: you (or asciidoctor / graphviz /
mermaid) render it, which keeps aden offline and deterministic. Language-agnostic.

[source,bash]
----
aden viz cmd_understand                        # blast radius (dependents at risk), Mermaid
aden viz cmd_understand --mode reach           # dependencies it relies on (downstream reach)
aden viz cmd_understand --mode connectivity    # both directions (callers + callees)
aden viz --mode communities --format dot       # functional clusters as DOT cluster_* boxes
aden viz cmd_understand --depth 3 --format dot # deeper view, Graphviz DOT
aden viz cmd_understand -j                      # JSON seam (-j aliases --format json)
----

The first argument is a symbol — a bare name like `cmd_understand` or a full
`aden://…` anchor; omit it for `--mode communities` (a whole-graph view).

|===
|Flag |Description |Default

|--mode |View: `blast` (dependents at risk if the anchor changes — agrees with `impact-diff`), `reach` (dependencies it relies on — agrees with `query --impact`), `connectivity` (both directions), `communities` (clusters), or `graph` (whole-graph view model, JSON-only) |blast
|--depth |Max hops to include (blast/reach/connectivity) |2
|--format |Output: `mermaid`, `dot`, `asciidoc`, or `json` |mermaid
|--full |For `--mode graph`: emit the whole graph with no importance cap |false
|--scope <SUBDIR> |Restrict to sources under this project-relative path (e.g. `net/`) — slices and community detection run on the subtree |
|--resolution <GAMMA> |Community-detection resolution γ (default `1.0`; higher = finer clusters) |1.0
|===

`blast` and `reach` use the same impact-edge set as the `impact-diff` command and
differ only in direction (ADR-007 §2: blast radius walks incoming dependents, reach
walks outgoing dependencies — named honestly, never conflated); the
`communities` view reuses `aden communities` and renders DOT `cluster_*` boxes (the
layout best suited to grouping). The `asciidoc` format wraps the Mermaid source in a
`[mermaid]` block so it renders inline in an AsciiDoc site.

`--mode graph` (JSON-only) emits the *whole-graph view model* — every node with its
full attributes `{anchor, label, group, community, kind, degree, file, line}` and every
typed edge among the kept nodes (containment `Contains`/`PartOf`, the genuine code↔prose
`Documents`, calls, etc.). Nodes are ranked by total degree (importance) and capped
(default 800) so large projects stay manageable; `total_nodes`/`shown_nodes` report the
cap, and `--full` emits the whole graph uncapped. This is the single payload the
interactive viewer slices client-side for its lenses.

=== view

Render a graph slice as an *interactive, offline* browser page and open it. Reuses
`viz`'s JSON slice, inlines it plus a vendored graph library into one self-contained
HTML (no CDN, no runtime network), and opens it in your default browser. Built in by
default (the `view` cargo feature is on); disable with `--no-default-features`.

[source,bash]
----
aden view                                       # the WHOLE graph + full git-history replay
aden view cmd_understand                        # blast radius centred on a symbol
aden view --mode communities                    # community overview → click to drill in
aden view cmd_understand --mode connectivity    # callers + callees
aden view --replay --max 200                     # cap the replay to the last 200 commits
aden view cmd_understand --no-open --out g.html  # just write the file (CI / remote)
aden view cmd_understand --editor zed            # 'open in editor' uses Zed
----

A bare `aden view` (no anchor) opens the *whole-graph* view — the full importance-ranked
graph — which also carries the git-history activity log, so ▶ replay walks the entire
project populating from the first commit. Big commits reveal in bounded batches so growth
stays smooth, and a level-of-detail filter keeps large graphs responsive (the density
slider dials the rest in).

|===
|Flag |Description |Default

|--mode |`graph` (whole graph; the bare-`view` default), `blast` (dependents at risk), `reach` (dependencies), `connectivity`, or `communities` (overview with click-to-drill) |blast¹
|--depth |Max hops (blast/reach/connectivity) |2
|--replay |Graph the git history: the graph is the symbols touched across commits, and a ▶ replay (scrubber, speed, date, item count) plays the project *populating* over time — nodes appear as commits introduce them |false
|--max |Replay: commits to include, oldest→newest (`0` = entire history) |0
|--editor |Editor for "open in editor" links: `auto` (probe PATH for code/codium/cursor/zed/idea and use the first installed), `vscode`, `cursor`, `vscodium`, `zed`, `idea`, or a custom `{file}`/`{line}` URI template |auto
|--no-open |Write the HTML but do not open a browser |false
|--out |Output HTML path |a temp file
|===

¹ The `--mode` flag defaults to `blast`, but a bare `aden view` with no anchor opens the
whole-graph view (it has no single symbol to centre on).

The page is dark, community-coloured, and degree-sized; hover for the short symbol
name, click for details, and *right-click a node* (or use the panel link) to open its
source at the right line in your editor via a `vscode://file…`-style URI — the browser
routes the scheme to the desktop app, so no server is involved. The community view is
*hierarchical*: clicking a cluster expands into its connected core, with a `← back`
control. Keyboard: `/` search, space play/pause, `f` fit, `b` *synapse mode* (the graph
fires like a neural net — signals travel the edges), `h` hide UI, `o` open in editor.
Cross-platform: the browser opener and editor URIs work on Linux, macOS, and Windows.

=== timeline

Time-travel viewer: bake every historical version of a file into a self-contained,
offline HTML page. Client-side JS handles comparison — no server required, works
from `file://`. Gated behind the `view` feature (on by default).

[source,bash]
----
# View the full history of a file (opens in browser)
aden timeline src/lib.rs

# Compare specific refs
aden timeline src/lib.rs --from HEAD~10 --to HEAD

# Cap to last 20 commits, write to file
aden timeline src/lib.rs --max 20 --out /tmp/tl.html --no-open

# Use an aden anchor URI
aden timeline "aden://module/myproject/src/lib.rs#my_fn"
----

The generated page shows:

* A **version timeline strip** (chips, oldest→newest) for every baked version.
* **Two selectors** (Base / Compare) defaulting to first commit vs working tree.
* A **"Compare to today"** button (sets Compare = working tree) and adjacent-step buttons.
* A **side-by-side line diff** computed client-side via LCS (no server, no Rust diff dep).

|===
|Flag |Description

|`<PATH>` |File path (repo-relative, absolute, CWD-relative) or `aden://` anchor URI
|`--from <REF>` |Oldest ref to include
|`--to <REF>` |Newest ref to include
|`--at <REF>` |Show a single version at this ref
|`--max <N>` |Cap baked versions to N most-recent commits (default: 60; 0 = all)
|`--out <FILE>` |Write HTML to this path instead of a temp file
|`--no-open` |Write the HTML but do not open a browser
|===

Files not tracked in git, binary files, and repos without git are handled gracefully
with clear error messages. Renames are followed via `git log --follow`.

=== impact-diff

Map a `git diff` to the symbols it touches and report the *blast radius* — every
symbol reachable downstream — before you commit. Reuses the same impact traversal
as `query --impact`; only the diff→symbol mapping is new.

[source,bash]
----
aden impact-diff                   # uncommitted working-tree changes
aden impact-diff --staged          # staged changes (git diff --cached)
aden impact-diff --since HEAD~1    # changes vs a ref (HEAD~1, main, a tag…)
aden impact-diff --since main -j   # machine-readable
----

|===
|Flag |Description |Default

|--since |Diff against this git ref instead of the working tree |working tree
|--staged |Analyze staged changes |false
|--json |Structured output (touched symbols, blast radius, risk) |false
|===

Reports each touched symbol's downstream count, the union blast radius, and a
heuristic risk tier (downstream breadth: 0 none / ≤5 low / ≤20 medium / else
high). A changed line that falls inside no known symbol (docs, comments, new
files) contributes nothing. Also available as the MCP `impact-diff` tool.

`--json` includes an `affected_tests` array: test-source anchors that have
`Tests` edges into the touched symbols or their downstream reach — so you see
at a glance which test files exercise the changed code. Human output shows up
to 20 entries; use `--json` for the full list.

=== overlay

Author an intent overlay for a symbol: durable `[human]`/`[agent]` notes that
survive `aden gen` and are delivered to readers (`asm`, `ask`). Takes an anchor
or bare symbol name and an optional `[DIR]`.

[source,bash]
----
# Annotate a symbol with a durable intent note
aden overlay assemble

# Target a fully-qualified anchor in a specific project
aden overlay "aden://module/app/B.java#Greeter.hello" --project /path/to/proj
----

|===
|Flag |Description |Default

|--json |Output JSON where supported |—
|--project |Aden project path (overrides CWD) |CWD
|===

== Health and CI Commands

=== heal

Detect drift between source and contracts.

|===
|Flag |Description |Default

|--propose |Generate patch proposals for review |false
|--fix |Auto-fix high-confidence drift (SignatureMismatch rewrites) |false
|--gc |Garbage-collect orphaned contracts (no matching source) |false
|--since <REF> |Limit scan to files changed since this git ref |
|--apply <ID> |Apply a specific proposal by ID |
|--watch <DIR> |Watch directory and auto-heal on changes |
|===

[source,bash]
----
# Scan for drift
aden heal .

# Generate proposals for review
aden heal . --propose

# Auto-fix high-confidence issues
aden heal . --fix

# Garbage collect orphaned contracts
aden heal . --gc

# Limit to files changed since git ref
aden heal . --since HEAD~5

# Apply a specific proposal
aden heal . --apply 12345

# Watch mode (auto-heal on changes)
aden heal . --watch src/
----

|===
|Drift Event |Severity |Auto-Fix

|StaleHash |High |Yes — merge engine (store); or hash rewrite (on-disk legacy)
|SignatureMismatch |High |Yes — merge engine (store); or sig rewrite (on-disk legacy)
|MissingContract |Medium |Advisory
|OrphanAnchor |Medium |Yes (--gc)
|BrokenReference |Critical |No
|DeadLink |Low |No
|MarkdownDrift |High |No
|StaleMarkdown |Medium |No
|MissingMarkdownTemplate |Medium |No
|===

Aden is store-first: contracts live in the per-user project store (see
`aden store path`), not as on-disk `.adoc` stubs. Consequently:

- `StaleHash` and `SignatureMismatch` `--fix` for store-resident events routes
  through the three-way merge engine (`ContractState::apply`): it re-parses the
  source, reconciles against the last-emitted base snapshot, and layers the
  durable `[human]`/`[agent]` overlay as the working layer. On a *clean merge*,
  the fresh `Document` is written to the store and the base snapshot updated —
  equivalent to `aden gen` but gated so overlays survive. On a *conflict*
  (an overlay block tagged identically to a generated block), a `MergeReconcile`
  proposal with `[proposed]` conflict markers is persisted instead; the store is
  NOT mutated until the conflict is resolved via `aden heal --apply <id>`.
- Legacy on-disk contract files (`.adoc` stubs) still have their `:source_hash:`
  or `:source_sig:` line rewritten in place. A failure on any single event is
  logged and counted as skipped, never aborting the run.
- `MissingContract` is reported as *advisory*: rather than materializing a
  hand-written stub (which has no recorded `source_hash` and would immediately
  re-flag as `StaleHash` and self-drift), the proposal points at the source file
  and emits the regeneration command (`aden gen <src> --auto .`) to populate the
  store-resident contract.
- `aden heal --apply <id>` for a `MergeReconcile` proposal re-runs the merge
  engine and writes the result to the store on a clean merge; conflicting
  proposals are refreshed in place with updated `[proposed]` markers.
- `--gc` prunes a contract whose source file is no longer a *live* source — this
  covers files deleted from disk as well as files newly excluded by
  `.adenignore`/`.adenallow`.
- `MissingMarkdownTemplate` is emitted only for repos that already participate in
  aden's markdown convention (at least one known doc such as `NOTICE.md` /
  `MAINTAINERS.md` exists) and lists which known doc is absent.

=== ready

Fast, dev-facing pre-commit combo. Runs aden's own gates only — no external
tool dependencies. Use this before every local commit.

[source,bash]
----
aden ready .
aden ready . --fix    # forward --fix to linter and high-confidence heal
----

Steps (fail-fast on hard gates):
1. `aden gen` — index changed source
2. `aden lint` — heuristic source checks
3. `aden check` — reference validation
4. `aden heal` drift scan — doc drift detection (reportable signal; with `--fix`,
   high-confidence auto-fixes are applied first, then re-scanned)
5. `aden audit` — OWASP security scan

=== ci-check

Full CI gate suite. Use this before pushing to remote — includes external tool
checks not in `ready`.

[source,bash]
----
aden ci-check .
----

Steps (in order):
1. `aden check` — reference validation
2. Constitutional firewall — policy enforcement
3. `aden test` — test execution
4. `aden lint` — source linting
5. Secret scan — hardcoded credentials
6. Accreditation check — license compliance
7. OWASP audit — security vulnerabilities
8. Merge conflict markers — clean diffs
9. Insecure protocol — no HTTP/FTP
10. Cargo clippy — Rust best practices
11. Cargo audit — dependency vulnerabilities
12. Contract freshness — drift detection

=== mcp

Model Context Protocol integration.

[source,bash]
----
# Install for all platforms
aden mcp install --all

# Install for specific platform
aden mcp install --platform opencode
aden mcp install --platform claude
aden mcp install --platform cursor

# Uninstall
aden mcp uninstall --all
aden mcp uninstall --platform opencode

# List configured platforms
aden mcp list
aden mcp list --name aden-plan

# Start HTTP server for CI/agents
aden mcp serve --port 3030
----

Each platform reads MCP servers from its own config file and schema. `aden mcp
install` writes the project-local file when one applies, falling back to the
user-global path, and merges the named server entry into any existing config without
disturbing other servers.

Claude Code defaults to `user` scope, which registers one global server named
`aden` via `claude mcp add -s user`. Running that command again from a different
folder does not create another folder-bound server. For one Aden MCP server per
repository, use `aden mcp install --platform claude --scope project` from each
repository, or pass `--project <PATH>` explicitly.

For local agent orchestration, prefer presets over one broad MCP entry. For
example, a Codex project can keep a small exploration profile and a broader
verification profile in the same `.codex/config.toml`:

[source,bash]
----
aden mcp install --platform codex --scope project --preset explore
aden mcp install --platform codex --scope project --preset verify
----

`install`/`uninstall` flags:

|===
|Flag |Description

|--platform <PLATFORM> |Target one platform: `opencode`, `claude`, `cursor`, `codex`, `zed`, `windsurf`
|--all |Apply to all platforms, not just detected ones
|--scope <SCOPE> |`user` (global) or `project` (local). Default: `user` for Claude Code, `project` otherwise
|--preset <PRESET> |Workflow preset: `explore` (`aden-explore`, essential), `verify` (`aden-verify`, standard), or `admin` (`aden-admin`, full)
|--name <NAME> |Override the MCP server entry name to install, list, or uninstall. Default: `aden`
|--binary <PATH> |Path to the `aden-mcp` binary to register
|--project <PATH> |Project directory the server should serve
|--dry-run |Show what would change without writing files
|--surface <LEVEL> |Override the preset/default tool surface: `essential`, `standard`, or `full` |essential
|===

|===
|Platform |Config Path |Format

|opencode |`.opencode/opencode.json` or `~/.config/opencode/opencode.json` |JSON, `mcp` key (`type: local`)
|claude |`.mcp.json` (project-scoped) |JSON, `mcpServers` key
|cursor |`.cursor/mcp.json` or `~/.cursor/mcp.json` |JSON, `mcpServers` key
|codex |`.codex/config.toml` or `~/.codex/config.toml` |*TOML*, `[mcp_servers.aden]` table
|zed |`.zed/settings.json` or `~/.config/zed/settings.json` |JSON, `context_servers` key (`source: custom`)
|windsurf |`~/.codeium/windsurf/mcp_config.json` (user-global only) |JSON, `mcpServers` key
|===

== Sync Command

=== sync

Run `gen` + `check` + `heal` (with garbage-collection) in one pass. Use this
to reconcile the knowledge graph and doc contracts after large changes, merges,
or when the store may have accumulated stale entries from deleted files.

[source,bash]
----
aden sync .
aden sync . --no-gc   # skip store garbage-collection (faster, leaves orphans)
----

NOTE: `sync` is for *graph reconciliation*, not the daily pre-commit loop. For
pre-commit use `aden ready`; for the full external-tool gate use `aden ci-check`.

=== understand

One-shot symbol comprehension. Replaces the manual chain of `locate` →
`query --backlinks` → `query --impact` → `asm`.

[source,bash]
----
aden understand <SYMBOL> [DIR]
aden understand Database::connect .
aden understand connect . --budget 8000
aden understand connect . --json
----

Returns in a single report:
- Anchor resolution and definition location
- Backlinks — who calls / references this symbol
- Impact — what this symbol calls downstream
- Assembled context block within `--budget` tokens (default 4000)

`--json` emits a single object `{symbol, anchor, definition, backlinks, impact, context}`
for programmatic use.

=== status

Show project health status at a glance. Takes only an optional `[DIR]`
(default `.`) — there are no meaningful `--json` or `--verbose` modes.

[source,bash]
----
aden status
aden status .
----

Prints a compact summary:
- the project path
- the active `.aden` store path
- a health-score percentage with an emoji (✅ / ⚠️ / ❌)
- an orphan-document count
- a savings estimate: session and all-time counts of aden calls, tool calls saved, and tokens saved vs grep-and-read

== Output Formats

Aden commands default to the format best suited for their intended consumer. LLM-facing commands default to stripped, token-dense prose. Human-facing commands default to human-readable output.

=== LLM-Facing Commands

These commands default to formats optimized for AI agents consuming context:

|===
|Command |Default Format |What It Means

|`aden asm` |`--format llm` |Stripped prose — no `[[anchors]]`, no `|===` tables, no `:key: value` lines. Every token carries signal.
|`aden ask` |Uses `asm` internally |Same stripped prose default. No `--format` flag needed.
|`aden query` |`--format json` |Structured JSON for programmatic consumption.
|===

To get raw AsciiDoc from these commands (e.g. for an IDE renderer), opt in explicitly:

[source,bash]
----
aden asm --from mod-aden-core --format aden
aden query --from mod-aden-core --format table
----

=== Human-Facing Commands

These commands default to human-readable output:

|===
|Command |Default Format |What It Means

|`aden audit` |`--format text` |Color-coded text report for terminal reading.
|`aden locate` |`--format plain` |Human-readable symbol location with line numbers.
|`aden list` |Table |Terminal table with anchor names.
|`aden search` |Table |Terminal table with BM25 scores.
|===

To get machine-readable output, opt in:

[source,bash]
----
aden audit --format json
aden locate --symbol main --format json
aden search "authentication" --json
----

=== How `gen` Stores Output

`aden gen` is store-first: it compiles source into the knowledge graph in the
per-user project store (see `aden store path`; ADR-003) and emits no files
(there is no output-format flag). Read
commands (`ask`, `asm`, `query`, `grep`) serve LLM-ready context from the
store, and machine-readable output is available via `--json` where noted above.
