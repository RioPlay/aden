= ADR-003: Markdown Emission and Cross-Format Drift Detection

== Context
Aden's core strength is AsciiDoc as the native substrate (per <<adr-001>>), but real-world projects have legacy Markdown files (`AGENTS.md`, `CONTRIBUTING.md`, `README.md`, `NOTICE.md`) that AI agents and CI systems depend on. These files are currently invisible to aden:

. **No emission path**: Aden generates `.adoc` contracts but cannot emit equivalent `.md`
. **No drift detection**: `aden heal` only checks `.adoc` contracts against source, not `.md` files
. **Template gaps**: Files like `AGENTS.md` require manual updates when code changes

Result: Code health can be 100% while docs are stale.

== Decision
We will extend aden to support Markdown as a derived format while preserving AsciiDoc as the source of truth.

=== Core Principles
. **AsciiDoc remains primary**: All contracts, templates, and knowledge are authored in `.adoc`
. **Markdown is derived**: Aden emits `.md` from `.adoc` source, never the reverse
. **Unified drift detection**: Both `.adoc` and `.md` files are checked for staleness against source

=== Implementation

| Component | Change |
|-----------|--------|
| `aden-emit` | Add `emit_document_md()` parallel to existing AsciiDoc emitter |
| `aden-gen` | Add `--format markdown` flag; support `--merge` three-way merge |
| `aden-heal` | Add `MarkdownDrift` and `StaleMarkdown` event types |
| Templates | Add template variable expansion: `${crates}`, `${commands}`, `${modules}` |

=== Specification

==== Markdown Emitter (`aden-emit`)
[source,rust]
----
pub fn emit_document_md(doc: &Document) -> String {
    // Convert Document → GitHub-flavored Markdown
    // - `[[anchor]]` → HTML anchor comment
    // - `<<ref>>` → markdown link `[ref](#ref)`
    // - Tables → GFM syntax
    // - Includes → flattened (or warning)
}
----

==== Drift Events for Markdown
[source,rust]
----
pub enum DriftEvent {
    // ... existing events ...
    
    MarkdownDrift {
        md_path: String,
        template_source: String,  // what aden would generate
        actual_content: String,
    },
    StaleMarkdown {
        md_path: String,
        source_files_changed: Vec<String>,
    },
}
----

== Consequences

|===
|Factor |Impact

|Agent compatibility|AI agents (Claude, OpenCode) that read `.md` get fresh, auto-generated docs
|Legacy migration|Existing projects can adopt aden without rewriting markdown
|Dual maintenance|No: markdown is derived, never hand-edited (same pattern as contracts)
|Decision clarity|AsciiDoc = source, Markdown = output; no ambiguity
|===

== Risks

. **Confusion**: Users may edit `.md` directly, not realizing it will be overwritten.
  - *Mitigation*: Document the derived nature; use `[generated]` markers in markdown comments
. **Feature creep**: Markdown support could dilute AsciiDoc primacy.
  - *Mitigation*: This ADR explicitly preserves AsciiDoc as primary; markdown is emit-only
. **Drift complexity**: Detecting markdown drift requires template/expected-content tracking.
  - *Mitigation*: Store `.md` templates in `.aden/templates/` with hash validation
