= AP-104: Strict serialized response budgets

== Outcome

The complete response, not merely assembled content, remains within the caller's
budget and documented tokenizer tolerance.

== Current evidence

Assembler budgets exclude some CLI/MCP framing, stale hints, alternates, and
automatic budget boosts.

== Scope

Assembly rendering, CLI query output, MCP wrappers, and serialization tests.

== Acceptance

* Headers, receipts, provenance, alternates, supplements, warnings, and wrappers count.
* Base and effective budgets are explicit; strict mode never auto-boosts.
* MCP read tools request strict budgeting by default.
* Black-box tests cover all formats, Unicode, tiny budgets, stale hints, ambiguity,
  strict/automatic behavior, and transport serialization.

== Non-goals

Do not replace the existing assembler budget implementation or optimize retrieval quality.

== Failure modes and rollback

If the receipt cannot fit, return a minimal incomplete receipt rather than an
oversized or falsely complete response.

== Completion evidence

Format measurements, strict-mode fixtures, and transport golden tests.
