= AP-106: CLI, MCP, and documentation parity

== Outcome

A documented workflow and its CLI/MCP forms agree on syntax, defaults, errors,
schemas, outcomes, and meaning.

== Current evidence

Existing parity tests cover flags and enums, but examples and structured output
can drift from CLI behavior.

== Scope

ToolSpec, MCP adapters, CLI tests, command documentation, and response fixtures.

== Non-goals

No new MCP transport or remote-server support.

== Acceptance

* Preserve existing ToolSpec and flag/enum/coverage tests.
* Add positional, requiredness, default, example, response, and error parity.
* All read tools, including ask/asm/query/locate/understand, have versioned JSON.
* Golden fixtures prove semantic equality, not only accepted flags.

== Failure modes and rollback

Generated documentation must remain reviewable. Keep the central specification
small and test handwritten examples against it.

== Completion evidence

CLI/MCP/default/error/schema fixtures and clean documentation runs.
