[[dx-102]]
= DX-102: MCP agent contract

== Outcome

Agents never parse terminal prose to decide whether Aden data is fresh, bounded,
complete, ambiguous, or safe to use.

== Current evidence

Structured output flags intentionally omit several read tools, requiring agents
to infer freshness and truncation from prose.

== Scope

MCP capabilities, receipts, tool errors, and contract fixtures.

== Non-goals

No model-host-specific workflow or remote transport.

== Acceptance

* Capability discovery declares tools, effects, schemas, and output modes.
* Every read tool returns a receipt and no terminal chrome.
* Errors state safety and an exact recovery action.
* Contract fixtures cover every advertised MCP surface.

== Failure modes and rollback

Maintain protocol capability negotiation and preserve the last compatible schema
during migration.

== Completion evidence

Capability snapshots, response fixtures, and agent-consumption integration tests.

=== 1. Separate agent-usage trials from the legacy retrieval benchmark

Inspection found that `prompt_for` in `scripts/agent_bench.py` forces ask-first,
immediate synthesis, and selection of the first returned ambiguity candidate;
the README instead describes adaptive navigation. Existing tests intentionally
pin the deterministic prompt. This benchmark cannot measure free tool choice.

Add an opt-in, explicitly versioned agent-usage protocol to the existing harness;
keep legacy behavior/results identifiable and preserve the frozen task corpus.
Permit direct symbol navigation and exact source reads, retain unresolved
ambiguity, and avoid first-tool examples in neutral handoffs. Correct the README
to describe both protocols accurately. Own `scripts/agent_bench.py`,
`scripts/test_agent_bench.py`, and `scripts/agent-bench/README.md`.

Acceptance: legacy regression tests remain green; generated neutral prompts do
not prescribe ask/grep first or select candidate zero; reports identify protocol,
prompt, schema, model/settings, source revision plus dirty diff, and binary
fingerprints. Exercise a local fixture before any model trial. Rollback only
the opt-in protocol changes. This is the next implementation slice.

[[dx-102-next-evidence]]
=== 2. Record observed outcomes and verify consequential claims

Extend the existing event/adapter handling rather than add another runner.
`summarize_event` currently retains invocation names but drops outcomes, while
adapter trajectories are self-reported. Preserve that distinction in reports.
Derive counts, errors, nonempty responses, and retries from correlated recorded
events; missing or incomplete telemetry means unknown, never zero. Keep shell
failures, transport failures, tool errors, and valid needs_narrowing separate.

Add fixtures and a review rubric for the observed security mistakes: successful
output preservation/normalization versus error redaction, and a 4,000-byte
prefix versus total output including the truncation marker. Require actual
source locations and distinguish inspected facts from graph-derived inference.
Source identity must match the claim; routing confidence is insufficient.
Keep automated pattern scores separate from source-based review verdicts.

Acceptance: replay fixtures correctly count success, error, empty, duplicate,
retry and missing-event cases; model prose cannot change recorded totals.
The prior incorrect claims fail the rubric, corrected source-backed answers
pass. First-attempt results and reviewer-assisted completion stay separate.
Use a new fixture file for new cases; do not rewrite locked regression tasks.
Rollback additive reporting/fixtures independently of package 1.

[[dx-102-pilot-decision]]
=== Decision and validation

Use bounded handoffs with explicit file ownership, executable acceptance checks
and review of consequential claims. This sample supports the tested small
coding, ambiguity and current-source verification tasks. It does not support
unsupervised deployment-security certification. Plausible security observations
remain investigation leads until trust boundaries and exploitability are
verified. Several broad runs exceeded the requested 12-call budget; if this is
a hard requirement, enforce it in execution rather than rely on prose.

Counts cover observer calls only; unrelated host commands/edits are unobserved,
not zero. Every observed request starts a new MCP process, so this is not a
persistent-session concurrency/latency evaluation. Fixture isolation used task
instructions and post-run comparisons, not an OS sandbox. These small samples
are not population success rates or model rankings.

Validation: all 62 Python tests passed; the frozen regression dataset lock test
passed; roadmap validation (15 packets, acyclic), documentation anchor/policy checking
and diff checking passed. The prior
workspace/native MCP validation recorded above remains applicable; this slice
adds Python evaluation/reporting and a Rust comment correction. No commits,
pushes, global configuration changes, startup expansion or routing rewrite.
