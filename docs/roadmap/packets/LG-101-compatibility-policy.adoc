= LG-101: Public compatibility and versioning policy

== Outcome

Users and implementers know which Aden interfaces are versioned, how breaking
changes are introduced, and how long deprecated behavior remains supported.

== Current evidence

SemVer, generation logic versions, store recovery, CLI/MCP behavior, and
environment compatibility are documented separately without one public contract.

== Scope

CLI syntax/output/exit codes, MCP schemas, Context Receipt, graph schema,
store/cache formats, environment variables, and Rust library APIs. Define 0.x
rules, support windows, deprecation, migration, and rollback expectations.

== Non-goals

No interface migration or release pipeline implementation.

== Acceptance

* Every public surface has an owner and compatibility rule.
* Receipt and freshness state migrations have a declared path.
* Store rebuild versus migration behavior is explicit.
* CI-testable compatibility obligations are listed.

== Failure modes and rollback

An overly broad promise can freeze development. Mark experimental surfaces
explicitly and revise the policy only through a durable decision record.

== Completion evidence

Published surface inventory, migration policy, and compatibility test plan.
