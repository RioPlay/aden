= AP-101A: Context Receipt schema and migration contract

== Outcome

Every machine-readable result can describe its revision, freshness, coverage,
budget, retrieval, outcome, warnings, and schema version without transport-specific
semantics.

== Current evidence

`augment_read_json` injects only freshness fields into inconsistent CLI shapes,
and several MCP read tools do not expose structured output.

== Scope

Protocol-neutral receipt types plus CLI/MCP adapters and migration fixtures.

== Acceptance

* The receipt type lives outside CLI freshness implementation.
* The envelope is extensible without field collision.
* Existing CLI/MCP JSON migration is documented and compatibility-tested.
* Secret content cannot enter receipt metadata.

== Non-goals

This phase defines the envelope skeleton; AP-102 through AP-106 own field semantics.

== Failure modes and rollback

Keep legacy output available through the compatibility window. Never silently
wrap arrays or objects in shapes callers cannot negotiate.

== Completion evidence

Schema decision, compatibility fixtures, and reviewed CLI/MCP examples.
