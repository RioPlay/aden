[[migration-0-3-0]]
= Migrating to Aden 0.3.0

Aden 0.3.0 intentionally changes successful read-command output to JSON by
default. This is a pre-1.0 breaking CLI contract change; stores and indexes do
not require migration.

== Who is affected

Scripts that parse the default terminal output of `ask`, `asm`, `search`,
`grep`, `list`, `locate`, `understand`, `status`, or other read commands must
either consume JSON or request the human renderer explicitly.

== Before and after

[source,shell]
----
# 0.2.x: prose was the default
aden ask "How does authentication work?"

# 0.3.0: versioned JSON is the default
aden ask "How does authentication work?" | jq -r .context

# Preserve clean terminal prose
aden ask --human "How does authentication work?"
----

`asm` now returns a versioned object with a `documents` array. The historical
bare array remains available as `--format adg`.

[source,shell]
----
aden asm --from my_anchor | jq '.documents[]'
aden asm --format adg --from my_anchor
aden asm --human --from my_anchor
----

The legacy `--json` flag remains accepted. `--json` and `--human` conflict so a
caller cannot silently request two renderers.

== Strict budgets

`--strict` caps the complete serialized response. At extremely small budgets,
`ask` may omit optional routing metadata and return only `schema_version`,
`context`, and `truncated`.

== MCP

MCP tools already request structured output. Existing MCP clients should not
need changes, but clients that unwrap `ask` or `asm` should accept the versioned
CLI envelopes rather than parsing terminal prose.

== Rollback

Use `--human` as the immediate compatibility path. To restore the complete
0.2.x behavior, reinstall Aden 0.2.0. No store rollback is necessary.
