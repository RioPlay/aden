= plan-ux-human

Human Experience Improvements for Aden. Making the recommended workflow obvious and effortless.

== Problem Statement

Aden has excellent tools (`ci-check`, `watch`, `gen --merge`, `heal --propose`) but users don't discover them naturally. The current workflow requires reading multiple docs to understand:
- When to run which command
- How to prevent drift proactively
- What "safe" vs "aggressive" healing looks like

== Goals

. Make the recommended pre-commit workflow obvious
. Provide scaffolding for automation (hooks, scripts)
. Reduce decision fatigue for new users
. Make "safe" the default for humans who don't want to think about it

== Workflow: The "Safe Path"

For most users, this should be the obvious path:

[source,bash]
----
# Development: Use watch to auto-regenerate
aden watch .

# Before commit: Run CI gates
aden ci-check .

# If ci-check fails heal, review then fix
aden heal . --propose   # Review first
aden heal . --fix       # Only if confident
----

[source,bash]
----
# OR for aggressive automation (CI pipelines):
aden gen src/ --auto
aden ci-check .
----

== Implementation Notes

=== Hooks Philosophy

- Hooks are optional, not forced
- Provide samples, user edits to `.git/hooks/` 
- Document how to install: `cp .aden/hooks/pre-commit .git/hooks/`

=== UX Principles

. **Explicit over implicit** - Don't surprise users with auto-gen
    - BUT make the "right thing" easy to do
    - Provide clear warnings when doing potentially destructive things
. **Safe defaults for humans** - `ci-check` before commit, `propose` before `fix`
- **Opinionated guidance** - Tell users what to do, don't make them figure it out
