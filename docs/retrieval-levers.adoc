= Retrieval levers: the dual substrate
:toc:

[[retrieval-levers]]
Aden retrieves over two complementary substrates, and the right one depends on what the text is. Code is best served by the corpus's own co-occurrence structure; prose is best served by an English dictionary. Aden exposes one lever for each, plus an auto-gate that picks per query.

== The two substrates

[cols="1,2,3,2",options="header"]
|===
|Domain |Lever |Signal |Measured lift
|Code |PPMI rerank |Corpus co-occurrence (no external dictionary) |MRR 0.216 -> 0.289
|Prose |OEWN synonym expansion |Open English WordNet synonymy, grounded to corpus vocab |R@1 1/42 -> 41/42
|===

Both findings come from A/B harnesses under `crates/aden-cli/tests/` (`compound_ab`, `prose_lexicon_ab`, `lexicon_routing_ab`).

== Why not one lever for both

The two substrates are not interchangeable, and mixing them backfires:

* On code, an external dictionary *dilutes* the corpus signal: PPMI-only reranking scores MRR 0.289, while PPMI plus OEWN synonyms drops to 0.247. Code synonymy is corpus-specific identifier vocabulary, not English dictionary synonymy.
* On prose, dense embeddings capture only about half of the synonym bridges (R@1 20/42) that the dictionary captures (41/42), and the dictionary still adds on top of a hybrid base (HYBRID+OEWN 41/42 vs HYBRID 16/42). The dictionary is complementary to dense, not redundant.

== Using the levers

Auto-gating is **off by default**. Set `ADEN_LEXICON_ON` to opt in; it is then routed by the detected text (see below). The switches are environment variables:

`ADEN_LEXICON_ON`:: Enable auto-gating. The lever is chosen per query: prose queries get expansion, code-shaped queries get rerank.
`ADEN_LEXICON_OFF`:: Kill switch. Overrides `ADEN_LEXICON_ON` and disables auto-gating even when that variable is set (plain retrieval, exactly as before the levers).
`ADEN_LEXICON_EXPAND`:: Force the prose lever regardless of auto-gating state. Grounds and appends OEWN synonyms to the query before retrieval. Grounding means a synonym is kept only if it tokenizes entirely into the corpus vocabulary, so the dictionary only ever adds words the corpus actually uses.
`ADEN_PPMI_RERANK`:: Force the code lever regardless of auto-gating state. Reranks the top window of results by corpus PPMI co-occurrence between the query terms and each candidate's terms.

Both levers are grounded and corpus-gated: the prose lever no-ops when the OEWN store is absent or the corpus lacks the vocabulary, and the code lever only fires when the query looks code-shaped.

=== How auto-gating decides

* *Expand* (`!codey`): when the query is not code-shaped. Grounding self-gates on vocabulary the corpus lacks, so this is a no-op on a code-only corpus and decisive on prose.
* *Rerank* (`codey`): when the query looks code-shaped — `query_looks_codey` checks for snake_case, camelCase, `::`, paths, and code punctuation. The check is on the query text only, not on corpus properties.

So a code-identifier query reranks, a prose query over a docs corpus expands, and a natural-language question over a code repository expands only (it is not code-shaped, so `codey=false`). Example: on the aden repository, `aden search "combine ranked lists"` in auto mode promotes `rrf_fuse` to rank 1, which the default ranking misses.

== Setup

The prose lever reads the OEWN lexical overlay store (a per-user overlay, never the project `.aden/store`):

[source,sh]
----
# Convert OEWN to triples, then build the overlay store (~/.cache/aden/lexicon)
python3 scripts/oewn_to_triples.py --all
cargo test -p aden-cli --test build_lexicon_store -- --include-ignored
----

The code lever's hybrid base uses dense embeddings, so build with `--features dense` for the strongest result (it degrades to BM25 otherwise).

== Benchmarks

Prose, synonym-bridge probes (query is a dictionary synonym absent from the gold article, so only a dictionary can bridge it), BM25-only unless noted:

[cols="2,1",options="header"]
|===
|Arm |prose R@1
|BASELINE |1/42
|+OEWN |41/42
|+MOBY |16/42
|DENSE alone |20/42
|HYBRID + OEWN |41/42
|ORACLE |42/42
|===

Code, rank-of-gold over hybrid base (`compound_ab`):

[cols="2,1",options="header"]
|===
|Arm |code MRR
|DENSE |0.201
|HYBRID 1:5 |0.216
|RR + PPMI (derived) |0.289
|RR + PPMI + OEWN |0.247
|===

OEWN beats Moby substantially on prose (curated WordNet vs broad noisy thesaurus), and merging dictionaries adds nothing over OEWN alone, so the shipped prose lever is OEWN.

== MCP

The MCP `ask` and `search` tools shell out to the `aden` CLI, so they inherit these levers automatically. Auto-gating is off by default; set `ADEN_LEXICON_ON` in the MCP server environment to enable it. Build the OEWN lexicon store to get the prose lever. Use `ADEN_LEXICON_OFF` as a kill switch to override `ADEN_LEXICON_ON` if needed. No tool-schema change is needed: the levers are deployment configuration, not per-call parameters.

== Status

Auto-gating is **off by default** (opt-in via `ADEN_LEXICON_ON`). PR #39 enabled it by default after an end-to-end OFF vs ON bench with the shipped binary showed prose synonym-bridge R@1 went 0/15 -> 15/15 and code rank-of-gold improved (e.g. `rrf_fuse` 18 -> 1, MRR 0.216 -> 0.289 in the harness). PR #40 reverted that default due to regressions on external repos (prose MRR regressed; tanstack dropped significantly), so auto-gating is now opt-in only. Set `ADEN_LEXICON_ON` to enable; use `ADEN_LEXICON_OFF` as a kill switch to override `ADEN_LEXICON_ON`. The levers are grounded and corpus-gated, so they no-op where they would not help. ConceptNet is excluded from the lexical overlay (CC-BY-SA ShareAlike, incompatible with aden's AGPL distribution); see `LEXICON-SOURCES.md` when a prebuilt store is shipped.
