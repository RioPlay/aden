= module::aden-cli

== Objective
User-facing binary for the Aden toolchain. Orchestrates all crates through a unified CLI.

== Commands (Implemented)

|===
|Command |Arguments |Behavior

|`aden init`|`[DIR]` (default `.`)|Scaffold `.agent/` templates and `.adenignore` in the target directory
|`aden new`|`--lang <lang> --path <dir> <name>`|Create a new project from a language template with Aden scaffolding
|`aden kickoff`|`--interactive --name <name>`|Create a kickoff document for a new initiative (interactive or from a brief)
|`aden workflow`|`--from <template> [--out <file>]`|Instantiate templates with substitutions and chain documents
|`aden gen`|`<PATH> [--out-dir <dir>] [--auto]`|Parse source file(s) and emit `.adoc` / `.aden` contracts to stdout or `--out-dir`
|`aden check`|`<DIR>` (default `.`)|Verify refs, anchors, cycles, orphans, and source_hash integrity
|`aden graph`|`--from <anchor> --depth <n> <DIR>`|Output graph neighborhood as a debug report
|`aden asm`|`--from <anchor> --depth <n> --budget <tokens> [--edge-types TYPES] [--out FILE] <DIR>`|Assemble context prompt from graph via BFS
|`aden query`|`--from <anchor> [--edge-type <type>] --depth <n> <DIR>`|Return JSON array of reachable nodes
|`aden query`|`--backlinks <anchor> <DIR>`|Return JSON array of nodes with incoming edges to target
|`aden query`|`--impact <anchor> <DIR>`|Return JSON transitive closure over dependency edges (blast radius)
|`aden ask`|`<QUESTION> [DIR] [--from <anchor>] [--budget <tokens>] [--model <model>]`|Natural-language question → search → intent classification → assembled context
|`aden search`|`<QUERY> <DIR>`|Full-text inverted-index search. Prints ranked results with snippets
|`aden locate`|`<SYMBOL> <DIR>`|Locate a symbol definition or its call sites in the graph
|`aden watch`|`<DIR>`|Watch source files and auto-regenerate contracts on change
|`aden heal`|`<DIR>`|Self-healing documentation engine: scan for drift, propose patches, apply reviewed changes
|`aden ci-check`|`<DIR>`|Run all local CI gates (check, heal, test, secret-scan, audit)
|`aden doctor`|`<DIR>`|Diagnose environment: tool versions, repo health, signing keys
|`aden review`|`--since <ref>`|Semantic review of changes since a Git ref, with token budgeting
|`aden session`|`--agent-id <id> --task <task> --files <files> --status <status> <DIR>`|Atomic session lock: append entry to `.agent/session.adoc`
|`aden licenses`|`<DIR>`|Generate third-party attribution report from `Cargo.lock`
|`aden audit`|`<DIR> [--format text|json|adoc] [--strict]`|OWASP-style security audit: scan source for vulnerability patterns
|`aden mcp`|`[DIR]`|MCP (Model Context Protocol) integration management
|`aden --version`|none|Print version
|`aden --help`|none|Print help, including subcommand help
|===

== Implementation Notes

- CLI uses `clap` derive macros with subcommand enums.
- `init` embeds template files at compile time via `include_str!`.
- `gen` delegates to `aden_parse::parse_file` and `aden_parse::parse_directory`.
- `check` aggregates anchors across all `.adoc` / `.aden` files, builds full graph via `aden_graph`, verifies `:source_hash:` via `aden_graph::integrity::check_hashes`.
- `graph` performs BFS from `--from` anchor up to `--depth`.
- `asm` assembles within `--budget` tokens using BFS traversal from `--from`.
- `query` emits JSON via `serde_json`. Sub-modes: `--from`, `--backlinks`, `--impact`.
- `ask` is the AI-facing entry point: search → classify intent → assemble → optionally send to LLM via `ollama:<name>` or `openai:<name>`.
- `search` uses `aden_index::Index` with TF-based scoring.
- `watch` uses the `notify` crate with recursive watchers.
- `heal` compares source hashes and signatures; `--propose` generates patches.
- `ci-check` runs `check`, `heal`, workspace tests, secret scan, and `audit`.
- `doctor` checks `rustc`, `cargo`, `git`, `aden` versions and verifies `.agent/` health.
- `audit` performs regex-based SAST for OWASP Top 10 patterns across supported languages.
- `mcp` starts or configures the Model Context Protocol server.
