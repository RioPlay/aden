= Experimental and Standalone Crates

This document tracks crates in the aden workspace that are **not yet fully integrated** into the core functionality.

== Status Legend

|===
|Status |Meaning |Action

|`core` |Fully integrated, actively used |No action needed
|`experimental` |Implemented but not integrated |Consider integration or removal
|`standalone` |Separate tool/binding |Consider external repo
|===

== Experimental Crates (Not Integrated)

None at present. The previously-tracked experimental crates (`aden-api`,
`aden-attest`, `aden-simulate`, `aden-telemetry`) were **removed** on 2026-06-02:
they had zero workspace dependents, were not wired into any binary, and existed
only as roadmap scaffolding (Phase 4-6). Their roadmap intent is still recorded
in the "Phase 1-6 Crate Map (Planned)" table in `docs/context.adoc`; the code can
be reconstructed from git history if/when those phases are picked up.

== Core Crates (Fully Integrated)

These crates are **actively used** and form the core aden functionality:

- `aden-core` - Schema and types
- `aden-parse` - Language parsers
- `aden-emit` - Contract emission
- `aden-graph` - Knowledge graph
- `aden-index` - Full-text search
- `aden-asm` - Context assembly
- `aden-cli` - Main binary
- `aden-mcp` - MCP server
- `aden-heal` - Self-healing
- `aden-propose` - Patch generation (used by heal)
- `aden-policy` - Constitutional directives
- `aden-store` - fjall LSM-tree persistence (`.aden/store`)
- `aden-diagnose` - Deterministic diagnostic scanner (backs `aden diagnose`)

NOTE: `aden-mcp` is integrated but unusual — it has no `aden-*` crate
dependencies. It shells out to the `aden` binary as a sibling process
(`resolve_aden_binary` + `tokio::process::Command`) rather than linking the
core crates directly.

== Governance

New crates should start as:
1. Features in existing crates (preferred)
2. Experimental crates with clear integration path
3. Standalone crates only with strong justification

Experimental crates older than 12 months without integration plans should be:
- Archived to separate repos, or
- Removed from the codebase
