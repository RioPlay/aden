[[adr-005]]
= ADR-005: Project-Tree Footprint and Opt-In Tracking of `.aden/`

[sidebar]
.What is an ADR?
****
Architecture Decision Records capture why a decision was made, not just what
was decided. No code should implement this decision before the ADR is accepted.
****

== Context

<<adr-003>> moved the rebuildable graph store and caches out of the project tree
and shrank in-tree `.aden/` to "durable intent" (`overlays/`, `constitution.adoc`,
`hooks/`). It also decided that durable intent *should be committed* so it travels
with the repo, and the implementation sketch says to "update `.gitignore` to track
those".

Three things have since pulled against that decision:

. *A direct contradiction in our own docs.* ADR-003 says commit the durable intent;
  `AGENTS.md:43` says "Never commit `.aden/` — build artifact, in `.gitignore`".
  Both are shipped. An implementer reading the repo cannot tell which is true.
. *`init` still taints beyond `.aden/`.* Today `aden init` unconditionally writes
  `.agent/` (a ~17-file template workspace), a root `.adenignore`, and — unless
  flag-gated per <<adr-004>> — touches root `AGENTS.md`. The footprint the user
  sees on first run is much larger than "one `.aden/` folder".
. *Config is scattered.* Per-project settings live across `aden.toml` (root),
  `.adenignore`/`.adenallow` (root), `.aden/project.conf`, and several `ADEN_*`
  env vars. There is no single in-tree config file.

The forces:

. *The project tree must stay pristine by default.* The strongest expression of
  ADR-003's own first force ("rebuildable artifacts do not belong in the working
  copy") is to taint the tree only when the user asks — even for `.aden/` itself.
. *Durable intent still has real value when shared.* A team's `constitution.adoc`
  (the CI firewall), `hooks/`, and `overlays/` are worth versioning. Silently
  dropping them is worse than a dirty tree: a teammate's `aden ci-check` would
  `SKIP` the constitutional firewall with no signal that governance was lost.
. *Decisions should be explicit, not defaulted.* Whether `.aden/` is committed is
  a real choice with team consequences; it should be made knowingly at `init`,
  not inherited silently.
. *Retrieval is eval-tuned, not user-tuned.* BM25 (`k1`/`b`), RRF (`k`), the
  coverage weight, stemming, and the index version are validated by the retrieval
  eval harness. Exposing them as per-project knobs re-opens the overfitting trap
  the devlog already retracted once. They must stay hardcoded.

== Decision

=== 1. Only `.aden/` may appear at the project root

Everything aden scaffolds lives under `.aden/`. The `.agent/` workspace becomes
`.aden/agent/`, and the ignore/allow files become `.aden/ignore` / `.aden/allow`.
The single exception is root `AGENTS.md`, which is an ecosystem-standard file other
harnesses auto-load (<<adr-004>>) — aden injects only its fenced block, it does not
relocate the file. No other top-level file or directory is created.

=== 2. One in-tree config file: `.aden/config.toml`

Per-project, intent-bearing settings consolidate into `.aden/config.toml`:

[source,toml]
----
[profile]                 # was aden.toml — redaction / visibility
mode = "internal"
redact_fields = ["author_email", "source_file"]

[git]
track = false             # see §3 — default: nothing in .aden/ is committed

[retrieval]
hybrid = false            # opt into dense embeddings (was ADEN_BGE_MODEL_DIR-only)

[defaults]                # per-repo CLI defaults (NOT retrieval math)
ask_budget = 4096
asm_depth = 3
----

Retrieval ranking parameters are deliberately *absent* — they remain hardcoded
constants validated by the eval harness, not config keys.

=== 3. Tracking `.aden/` is opt-in; the default is "ignored"

`git.track` defaults to `false`. The mechanism is a generated `.aden/.gitignore`,
which is *self-contained* — it never edits the repo-root `.gitignore`:

* *`track = false` (default).* `.aden/.gitignore` contains a single `*`. Nothing
  under `.aden/` is committed; git sees no tracked content there, so the folder is
  effectively invisible. The tree stays pristine with zero edits to user files.
* *`track = true` (opt-in).* `.aden/.gitignore` ignores `*` then re-includes
  *durable-intent only* — `!config.toml`, `!constitution.adoc`, `!ignore`,
  `!hooks/`, `!hooks/**`, `!overlays/`, `!overlays/**`. Rebuildable artifacts
  (`store/`, `cache/`, `proposals/`, `*-cache.json`) are *never* re-included, even
  when tracking is on.

This resolves the contradiction by promotion, not deletion: `AGENTS.md:43`
("`.aden/` is ignored") becomes the *default* truth, and ADR-003's "durable intent
travels with the repo" becomes the *opt-in* behavior rather than the default.

=== 4. `aden init` is opt-in and selectable

`init` makes no tracking or agent-file change without an explicit choice:

. *Interactive (TTY).* A picker, all destructive options *off* by default:
  - Track `.aden/` governance in git so it travels with the repo? — default *No*.
  - Seed the aden guidance block into an agent file? — *Skip* (default) /
    detected file in cwd (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`,
    `.github/copilot-instructions.md`) / custom path. (Governed by <<adr-004>>.)
. *Non-interactive (no TTY: CI, scripts).* Never prompt. Flags drive everything:
  `--track` / `--no-track` (default off), `--agents-file <path>` /
  `--no-agents-file` (default off). Absent flags ⇒ the pristine default.
. *Named tradeoff.* When the track prompt is shown it states the cost plainly —
  "off means teammates won't get your constitution, hooks, or overlays" — so the
  choice is made knowingly.

=== 5. AGENTS.md guidance block: safe across upgrades

<<adr-004>> already mandates marker-fenced, idempotent edits, and `seed_agents_md`
implements the happy path: replace only the bytes between the markers, append when
absent, never touch a byte outside them. But the current detection fails *toward
duplication* — the precise harm the guest rules exist to prevent — so this ADR
tightens four points:

. *Match a stable sentinel, not the decorated line.* Detection MUST key on a
  minimal, version-stable prefix (`<!-- BEGIN aden:guidance` … `<!-- END
  aden:guidance -->`), never the full marker text including its parenthetical.
  Today an exact-string match means any future reword of the BEGIN line stops
  recognizing blocks written by older aden, so `init` appends a *second* block
  instead of replacing the first — stale aden sections accumulate across upgrades.
. *Detect unbalanced markers.* A lone BEGIN or lone END (a user half-deleted the
  block) MUST be reported, not silently appended to. Appending past a dangling
  marker orphans it and compounds over time.
. *Collapse duplicates.* If more than one well-formed block is present (e.g. from a
  prior version's append bug), replace the first and remove the rest, leaving
  exactly one current block.
. *Write atomically.* Edit a user's hand-maintained `AGENTS.md` via temp-write +
  rename, so an interrupted run can never truncate or corrupt their file.

The block's body stays minimal (<<adr-004>>) and its trailing pointer tracks the
§1 relocation — "See `.aden/agent/aden-guide.adoc`", not the old `.agent/` path.

=== 6. Migration preserves already-committed `.aden/`

Flipping the default must not silently untrack files a repo already commits. On a
repo whose `.aden/` is already in git, `init`/`gen` treat `track` as `true` (detect
tracked `.aden/` content) and leave it tracked. The flip to `track = false` only
governs *new* `init` runs and repos that never committed `.aden/`. `aden doctor`
reports the effective state and how to change it.

== Consequences

Positive:

. *Pristine by default.* The common case — someone trying aden on a repo — never
  dirties `git status`. The footprint is one ignored `.aden/` folder, nothing else.
. *Self-contained ignore.* The root `.gitignore` is never touched; aden owns only
  `.aden/.gitignore`. No user file outside `.aden/` is mutated for tracking.
. *Contradiction resolved on the record.* One truth, with the other behavior
  reachable by an explicit, documented opt-in.
. *Honest, team-aware decision.* Sharing governance is a deliberate act with its
  cost stated, not a silent default in either direction.
. *Smaller, single config surface.* `aden.toml` + scattered env reliance collapse
  into one `.aden/config.toml`; ranking math stays unconfigurable and stable.

Negative / costs (with mitigations):

. *Team-governance footgun.* If a team wants shared governance and nobody opts in,
  `constitution.adoc`/`hooks/`/`overlays/` don't travel, and downstream
  `ci-check` silently SKIPs the firewall. *Mitigation:* `aden doctor`/`status`
  warns when durable intent exists locally but is untracked ("you have a
  constitution that teammates won't receive — `aden init --track` to share it").
. *Negated-`.gitignore` fragility.* Re-include patterns (`*` then `!…`) are a
  classic source of "why isn't this file tracked" bugs, especially for nested
  `hooks/**`/`overlays/**`. *Mitigation:* generate `.aden/.gitignore`
  deterministically from `git.track`; cover both modes with tests; never ask the
  user to hand-author it.
. *Two-sources-of-truth risk.* `git.track` (declared) can drift from the actual
  `.aden/.gitignore` (on disk) if a user hand-edits the latter. *Mitigation:*
  `config.toml` is the source of truth; `init`/`gen` regenerate `.aden/.gitignore`
  from it and `doctor` flags drift — but aden never overrides an explicit `git rm
  --cached` the user performed (tracked-state detection in §6 wins).
. *Reverses an "accepted" ADR.* ADR-003's "track those" line is superseded.
  *Mitigation:* this ADR records the supersession explicitly and ADR-003 gets a
  pointer note; `AGENTS.md:43` is updated to match the new default.
. *Migration surface.* Detecting already-tracked `.aden/` and not untracking it
  adds a code path. *Mitigation:* a single tracked-content check at `init`/`gen`;
  default-on `track` when found.

== Implementation sketch

. `AdenConfig` reads `.aden/config.toml`; `aden.toml` is read as a deprecated
  fallback that `init` offers to migrate.
. A `gitignore` writer in `aden-paths` (or `init`) generates `.aden/.gitignore`
  from `git.track`; called by `init`/`gen`. Two fixtures: `track=false` ⇒ `*`;
  `track=true` ⇒ `*` + the durable-intent allowlist.
. `init` gains `--track/--no-track` and the TTY picker; `.agent/` → `.aden/agent/`,
  `.adenignore` → `.aden/ignore`, `.adenallow` → `.aden/allow` (read both old and
  new paths during a deprecation window).
. Tracked-`.aden/` detection (`git ls-files .aden/`) drives the §6 migration.
. Harden `seed_agents_md`: prefix-match the markers (not the decorated line),
  detect unbalanced markers, collapse duplicate blocks to one, and write via temp
  + rename. Add tests for reword-across-versions, lone-marker, and double-block.
. `doctor`/`status` surface effective `track` state + the untracked-governance
  warning.
