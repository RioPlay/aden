= ADR-011: Read Snapshot — Concurrent Graph Reads Without fjall Contention

== Context

ADR-003 moved the rebuildable graph to a per-user fjall store keyed by project
root. That fixed subfolder pollution and gave each repository an isolated store,
but it did *not* solve **intra-project concurrency**.

When several agents (MCP sessions, IDE integrations, terminal `aden ready`) work
on the *same* repository, they all open the same fjall database at
`~/.local/share/aden/projects/<key>/store`. fjall enforces process-level
exclusive access — a concurrent open returns `FjallError: Locked`. Read commands
(`grep`, `ask`, `asm`, `query`, `locate`) shell out to the CLI, each subprocess
opens the store, loads the graph, and closes. Under normal multi-agent use this
overlap is constant.

ADR-010 scoped `ADEN_SKIP_AUTO_GEN=1` on MCP read tools to reduce *write*
contention during `gen`, but read opens still contend with each other and with
writers. Users correctly expect per-project isolation; the missing piece is
**parallel-safe reads within one project**.

The forces:

. Multi-agent workflows are a primary use case — several MCP servers on one repo
  is normal, not misconfiguration.
. The live fjall store must remain the write authority — `gen`/`regen`/`heal`
  writes cannot be duplicated or relaxed without corruption risk (see
  `store.lock` in `indexer/gen.rs`).
. Read paths already materialize an in-memory `AdenGraph` from store docs +
  edges (`aden-graph::cache::try_load`, `AdenGraph::build_from_storage`). The
  snapshot is that materialized view persisted to disk.
. Rebuildable artifacts belong in the per-user project dir (ADR-003) — a snapshot
  is rebuildable from `gen` and safe to delete.

== Decision

=== 1. Publish an atomic read snapshot at the end of every successful `gen`

After `link_store_edges`, `link_include_edges`, and `storage.flush()` complete,
`cmd_gen_inner` publishes a read-only artifact:

[source]
----
~/.local/share/aden/projects/<key>/graph.snapshot
----

Publication encodes docs + edges via `GraphBridge::load_from_storage` while the
store is still open, then writes them atomically (`graph.snapshot.tmp` →
`rename`) *after* the store handle drops — so a final fjall flush cannot leave
the live store newer than the snapshot file. Failures are **best-effort** (WARN +
continue); a missing snapshot falls back to fjall.

=== 2. On-disk format (version 1)

[cols="1,3"]
|===
|Field |Content

|Magic (8 bytes) |`ADENSNAP` — rejects random files
|Version (u32 LE) |`1`
|Payload |Postcard-encoded `{ docs: HashMap<String, Document>, edges: Vec<(String, String, EdgeType)> }`
|===

Postcard matches `aden-store` serialization. Version bumps are explicit; readers
reject unknown versions and fall back to fjall.

=== 3. Read path: snapshot-first with fjall fallback (Phase 2 of this ADR)

`aden-graph::cache::try_load` (and callers) attempt the snapshot when:

. `graph.snapshot` exists, AND
. the snapshot file's modification time is **≥** the newest mtime under the live
  `store/` directory (detects interrupted `gen` that updated fjall but crashed
  before publishing)

If either check fails, open fjall via `Storage::open_existing` (today's path).

Overlay folding (`aden_core::overlay::fold_overlay`) still runs in memory after
load — overlays stay in-tree under `.aden/overlays/` and are not embedded in the
snapshot.

=== 4. Writer queue + retry UX (Phase 2 — shipped)

Writers (`gen`, and therefore `ready`/`sync`) already serialized via
`store.lock`. Phase 2 makes waiting *visible* and retries fjall opens:

* **`FileLock::acquire_timeout_verbose`** — `NOTE:` every 5s with holder
  `pid` + age while waiting on `store.lock` (up to 10 minutes).
* **`FjallStorage::new_with_retry`** — after acquiring `store.lock`, retry
  `Database::open` when fjall returns `Locked` (readers still on the live DB),
  same 10-minute ceiling with periodic `NOTE:` lines.
* **`aden status`** — reports active store writer (if any) and read-snapshot path.
* **`aden_core::lock::read_holder`** — parses `store.lock` for diagnostics.

Second concurrent `gen` on the same project **waits** rather than failing
immediately; failure only after the full timeout with holder details.

== Consequences

**Positive:**

. N concurrent read subprocesses load the snapshot file (OS page cache) instead
  of opening fjall — eliminates `FjallError: Locked` on read-heavy multi-agent
  workloads.
. Preserves ADR-003 layout; snapshot is another rebuildable tier beside
  `cache/` and `gen-cache.json`.
. Thin MCP director unchanged — still shells out to `aden` CLI; reads become
  parallel-safe without an in-process daemon.

**Negative / costs:**

. Disk: one extra copy of docs + edges (~similar to in-memory graph size; aden
  repo ~100 MB store → snapshot proportional). Acceptable in per-user data dir.
. Publish adds one `get_all_documents` + `get_all_edges` pass at end of `gen`
  (already done for orphan reporting in non-quiet mode; marginal on large repos).
. Staleness vs working tree is unchanged — snapshot reflects last `gen`, not live
  edits; MCP `index_stale` signaling (ADR-010) still applies.

**Deferred (not in scope):**

. Coalesced `gen` queue (single writer batches overlapping refresh requests).
. Phase 3: in-process snapshot cache inside `aden-mcp` (load once per project).
. Phase 4: per-project graph daemon (`aden graphd`).
