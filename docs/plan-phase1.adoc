= Phase 1: Human Ergonomics (Weeks 3–4)

== Objective

AsciiDoc contracts must be as easy to edit as Markdown, but with machine superpowers.

== Theme

Human-centric tooling. LSP, IDE integration, and bootstrap workflows.

== Deliverables

|===
|ID |Deliverable |Crate |Status |Acceptance Criteria

|1.1 |LSP skeleton + text document sync |`aden-lsp` |Planned |`.aden` files open in VS Code, Zed, Neovim with AsciiDoc syntax highlighting
|1.2 |Hover on `<<ref>>` |`aden-lsp` |Planned |Shows target signature + `[human]` note + active `[agent]` directives + applicable `[override]`
|1.3 |Inline diagnostics |`aden-lsp` |Planned |Red squiggle when `[human]` claim contradicts `[generated]` AST reality
|1.4 |Code action "Generate `[security]` block" |`aden-lsp` |Planned |Inserts template from function signature; cursor lands in `:constraint:`
|1.5 |Rename refactoring |`aden-lsp` |Planned |Renaming Rust function updates all `<<anchor>>` references across `.aden` files
|1.6 |`aden bootstrap --from-markdown` |`aden-core` |Planned |Ingests `ARCHITECTURE.md`, `CONTRIBUTING.md`, `docs/security.md`; produces draft `[human]` blocks via constrained LLM
|1.7 |AsciiDoc profile reference docs |N/A |Planned |Single-page dialect spec + 10-minute onboarding guide published
|===

== Exit Gate

New engineer clones repo, installs LSP extension, edits `.aden` with hover/diagnostics within 10 minutes.
