[[project-file-browsing]]
= Complete project file browsing

== Usage

`aden tree --files [path]` lists discoverable source files, including documents,
configuration files and files without recognized symbols. Paths are relative to
the project root, even when the scope is a subtree. This is Aden's source view;
normal exclusions still apply.

Over MCP, call `tree` with `{"symbols":false}`. Omitted or true `symbols` retains
the existing compact code-symbol outline. These modes answer different questions:
use file browsing to find a document or configuration file, and the default mode
to inspect code structure.

File browsing returns `format: "files-v1"`, an `outline`, total and returned file
counts, and explicit truncation state. Symbol counts are zero because this mode
does not enumerate symbols. Output is bounded by default. For a clipped listing,
follow a narrower `next_actions` scope; those actions preserve file mode. Direct
CLI callers can use `--unlimited` to return all discoverable paths. `--files` and
`--symbols` conflict rather than silently selecting one.

== Priority decision

This increment addresses an observed omission in the first navigation step.
Before the change, MCP advertised a directory view for `symbols=false`, but JSON
dispatch forced the code-symbol view regardless. A scope containing only docs or
files without recognized code symbols could therefore appear empty.

The strongest alternatives were clearer recovery from rejected source reads and
better end-to-end acceptance for broad questions. Historical DX-102 evidence
identifies both as candidates, but does not establish their current causes or a
reliable fix. They should start with a small current reproduction. File browsing
had a directly reproduced defect and a bounded compatible repair with no new
dependencies or index policy.
