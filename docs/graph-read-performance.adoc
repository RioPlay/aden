[[graph-read-performance]]
= Request-scoped graph read performance

This increment targets repeated storage setup and whole-graph loading for bounded
queries. It does not introduce a daemon, a cross-request cache, or weaker freshness
checks. Baseline Git commit: `2172e0e35668f69af50cc43d37acb88ee9add297`.

== Changes and correctness boundaries

`query` now shares one request-scoped store handle between exact/natural symbol
resolution and graph traversal. When the keyed store is unavailable, resolution
and traversal use one immutable read snapshot. The handle is consumed and closed
before the final freshness observation and output.

Outgoing `--from`, incoming `--backlinks`, and outgoing `--impact` queries fetch reachable documents and typed
adjacency instead of constructing the entire repository graph. They load one
extra reachable result when a result limit applies, so omitted results can still
be reported as truncated. Parallel relationship types remain attached to their
source/target pair. Default structural-edge exclusions and impact-edge filters
remain in force.

Forward queries previously reused assembly-context pruning, which can intentionally
skip expansion through high-fanout intermediate hubs. In a reproduced two-hop
`entry -> dispatch -> 40 leaves` fixture, the baseline returned only two of 42
reachable symbols and reported `truncated: false`. Explicit graph queries now use
the exact directional traversal too; assembly-context pruning is unchanged.

Both independent source fingerprint observations remain. This change does not
turn filesystem notifications or modification timestamps into proof of freshness.
It also does not eliminate all repository-sized work: opening/recovering storage,
fingerprinting sources, and the snapshot fallback can still scale with the project.

Opt-in `ADEN_READ_TRACE=1` adds `anchor_resolve` and `graph_load` stages. The latter
includes the shared store's close/drop. The location of storage costs moves between
these stages when the handle is shared; end-to-end process latency is the primary
comparison. Inclusive stages must not be summed.

== Reproduction and measurement contract

Build matching release binaries with the same features, preserving the baseline
before rebuilding the candidate:

[source,powershell]
----
cargo build --release --offline -p aden-cli --no-default-features --features view --bin aden
python scripts/graph_read_bench.py --binary before=path/to/baseline.exe --binary after=target/release/aden.exe --files 512 --functions 24 --repetitions 4 --output graph-read-comparison.json
----

The synthetic fixture contains a three-function call chain plus disconnected
filler functions. Each repetition gives each binary an empty, isolated Aden data
directory. Arms share the same source paths and bytes. Cold reads include automatic
generation; every warm request uses a new CLI process. Priming and verification
requests are retained separately. Cold arms rotate a seeded starting order across
repetitions; post-edit arms reverse that order. Other warm cells use seeded
shuffles. With two arms, an even repetition count balances first-arm exposure.

The first post-edit graph request follows an equal-length symbol/call replacement
with the original modification timestamp restored. Subsequent impact/backlink
requests are labelled `warm_after_edit`; the post-edit search measures rebuilding
its previously primed search index. These are distinct states, not interchangeable
first-read-after-edit measurements.

Validators require exact canonical graph anchors, hop depths, edge types,
nontruncated query results, current source observations, and verified expected
source. Follow-up definition checks require the old definition to disappear and
the replacement to exist. Invalid JSON shapes, nonzero exits, and timeouts count
as failures; successful latency summaries do not erase failed attempts. Unit
tests exercise both accepted evidence and representative incorrect evidence.

Reports include binary SHA-256 identities, source-fixture hashes, all attempts,
and Windows main-process CPU time and peak working set. Child-process resources
are excluded. Other platforms report unavailable resource measurements as null.
Tracing must run separately from untraced comparisons. OS file caches are not
controlled; clearing Aden caches is not a cold-disk claim.

For an unchanged real repository, `scripts/repo_query_bench.py` compares complete
bounded `--from` and `--impact` result sets and their source observations. See
<<read-path-performance>> for that harness's contract.

== Remaining work after the first increment

This increment does not change `understand`, search-index serialization or broad
cache invalidation after generation. It does not establish general monorepo
scalability, tail latency, or LLM task productivity. The synthetic workflow is a
correctness-checked retrieval experiment, not an autonomous coding-task evaluation.
Persistent readers, incremental search postings, and notification-assisted
freshness require their own measured comparisons and recovery tests.

== Follow-up: lookup and understand reads

The next increment uses the preceding candidate as its baseline. `understand`
shares one request-scoped reader for resolution, alternate definitions, incoming
references, outgoing impact, and assembly context. Bounded graph views retain
their existing direction, edge filters, and assembly pruning. The reader closes
before source verification, assembly, and the final freshness observation.

Lookup coverage remains exhaustive: ranked matching considers all anchor keys,
including lower-ranked matches, rather than substituting the bounded symbol
lexicon. Symbol lookup retains its snapshot-first strategy; when a snapshot is
unavailable, its store fallback scans keys and fetches only selected documents.
The snapshot path still decodes the complete snapshot. An initial store-first
implementation made symbol lookup slower in both measured fixture sizes and was
rejected. `understand` and caller lookup use the shared store-first session.
Caller lookup considers every incoming `Calls` edge, including parallel
relationships, and deduplicates callers across matching definitions. A zero
result limit retains the definition count and match kind instead of entering
full-text fallback solely because the output list is empty.

The benchmark now also checks exact and natural `locate`, caller lookup, and
`understand` on a middle node with both callers and dependencies. It repeats these
checks after an equal-length edit with the modification timestamp preserved.
Definition metadata, verified source ranges, relationship direction, and required
context evidence are validated in addition to freshness. This fixture's single
call chain does not establish arbitrary-symbol or ambiguous-method coverage;
those behaviors need focused regression tests.

The final source passed 51 graph library tests, 275 CLI unit tests, 46 focused
read/freshness integration tests, and 47 tests across the three lint-cleaned
integration targets. All 15 benchmark-validator tests passed. Strict all-target
Clippy for `aden-graph` and `aden-cli` passed on Windows after mechanical borrow
and ceiling-division fixes and matching Unix platform guards on two test helpers;
no lint exemptions or weaker assertions were added.

The preserved baseline fails both new negative controls at the intended
assertions: zero-limit definition total was one instead of 13, and a caller with
parallel relationship types was omitted (zero instead of one). Raw failures and
their classification are retained in `.tmp/lookup-next/baseline-controls.json`.
An initial ambiguous-name fixture contained no recorded call edges on either
binary. Its corrected union test explicitly seeds the graph relationships and
does not claim that the parser resolves ambiguous duplicate names.

Focused tests cover exhaustive ranked matches, aliases, ambiguity, zero limits,
caller unions, parallel call edges, timestamp-preserving method edits, backend
errors, assembly pruning, and store/snapshot parity. Independent review found a
missing symbol-lookup fallback test; it was corrected by removing the fixture
snapshot, reading the accessible store, checking that the snapshot stayed absent,
then restoring and comparing results. Final independent review found no material
issue in the production changes or test design.

Both standalone MCP stdio tests passed with `ADEN_BIN` explicitly pinned to the
final release. Eight real-repository requests matched the baseline's lookup
results, caller sets, verified source, and assembled context on the unchanged
baseline Aden checkout. Evidence: `.tmp/lookup-next/repo-lookup-parity.json`.
These checks do not replace native checks on other operating systems or full CI.
