[[real-world-validation]]
= Real-world workflow validation

This exercise used full shallow checkouts of three independent upstream projects,
not Aden's own fixtures. It found three defects: missing CommonJS function
assignments, parser upgrades leaving unchanged projects on old graphs, and exact
definition questions depending on lexical search results. Regression tests and
fixes accompany this report.

[[real-world-validation-corpus]]
== Corpus and method

Run on Windows on 2026-09-09 UTC (2026-09-08/09 locally), starting with Aden 0.4.1
at Git commit `1f0163410488cc6d4e0b3b02df96f1d2d316c0e3`, generation logic version 12.
The first corrected build uses generation logic version 13. The follow-up below
uses version 14 and includes a larger checkout.

[cols="1,1,3,1",options="header"]
|===
|Project |Language |Upstream commit |Tracked files
|https://github.com/pallets/flask[Flask] |Python
|Git commit `d73fa1cdcbd8b1465c151db8924ba58b1dd14e35` |236
|https://github.com/expressjs/express[Express] |JavaScript
|Git commit `bed501c695a61886399ee622875f3be933c716d8` |213
|https://github.com/BurntSushi/ripgrep[ripgrep] |Rust

|===

Each run uses an isolated `ADEN_DATA_DIR`. Cold means an empty Aden index;
the operating-system file cache was not flushed. Timings include CLI startup
and JSON serialization. Warm lookup is the median of three calls. These are
small-to-medium projects and a single-machine sample, not a large-monorepo
benchmark, memory profile, or cross-platform performance claim.

The workflow covers first-use indexing, exact definitions, named and conceptual
questions, relationship context, nonexistent definitions, MCP initialization and
workspace discovery, and default simple-view export. A temporary Flask source
edit and its byte-for-byte restoration verify automatic refresh and pruning.
All upstream checkouts finish clean; upstream application code is not executed.
Implementation and caller expectations were checked against upstream source.

[[real-world-validation-findings]]
== Defects found and corrected

* Express defines public methods with assignments such as
  `res.json = function json(obj) { ... }`. These were absent from the graph:
  `locate res.json` failed and a JSON-response question routed to the changelog.
  Direct function assignments now retain the public binding, documentation,
  async status, and resolvable calls such as `this.send()` to `res.send`.
  Callbacks nested inside factory calls remain excluded from named API extraction.
* Installing an improved parser did not refresh an unchanged project's graph.
  Freshness manifests now include the generation-logic version. The actual old
  Express index refreshed on an ordinary read and exposed `res.json` without
  manual regeneration. An integration test verifies one refresh followed by a
  warm read with no refresh.
* Flask's `locate full_dispatch_request` succeeded while
  `ask "Where is full_dispatch_request defined?"` returned an empty result.
  Exact-name routing now reads indexed symbol identities independently of
  lexical postings, including when the initial text search is empty.
  Matching remains exact, with deterministic alternatives and no substring fallback.

[[real-world-validation-results]]
== Results and limits

The version-13 build passed all 33 required workflow checks. Two of the three
conceptual questions reached the expected implementation; the remaining miss
is described below. No upstream files were left modified.

[cols="1,1,1,1,1",options="header"]
|===
|Project |Cold index + tree |Warm locate median |Outline files / symbols |Viewer nodes / relationships
|Flask |2.71 s |0.81 s |66 / 1,359 |5,052 / 5,290
|Express |1.45 s |0.63 s |54 / 180 |226 / 721
|ripgrep |2.59 s |1.21 s |114 / 3,034 |3,795 / 13,505
|===

Regression compilation overlapped the later measurements; CPU and background
load were not controlled. In particular, a fresh ripgrep MCP process took
10.56 seconds during compilation, versus 0.91 seconds in the earlier trial.
These observations are not a speedup claim. The runner records every timing
so loaded and quiet runs can be compared without discarding slow results.

Outline counts are Aden's reported source inventory, not a completeness score.
Viewer counts also include document and derived graph nodes. Express's source
symbol count increased from 86 to 180 after assigned-function extraction was
corrected. Flask and ripgrep's top-level outlines explicitly report truncation
and recommend narrowing the subtree; Express's outline is complete.

Manual browser checks used the exported real-project graphs. Flask's dispatch
method showed its request-processing callees; following `handle_user_exception`
and returning with Back preserved the search. Ripgrep's `search_parallel` showed
both `run` and the optional index module's `read` caller, and `/` focused search.
The corrected Express view exposed `res.json` and its `res.send` relationship.
The views opened dark, loaded no external resources, and rendered bounded local
neighborhoods without a force simulation. Express interactions were verified
through DOM clicks after the browser automation click transport proved unreliable.

Version 13's conceptual retrieval was uneven: the question asking where ripgrep chooses
parallel versus single-threaded search routes to the guide, not the implementation
in `run`. Naming `search_parallel` succeeded. The follow-up fixes this miss and
promotes the three established implementation questions to required regressions.

Call relationships are heuristic. Version 13's Flask caller output included the containing
class aggregate as well as the actual `wsgi_app` method, and deeper dynamic-call
resolution can add noise. These results support navigation, not compiler-precise
proof of exhaustive callers or safe deletion. Computed JavaScript properties and
dynamic aliases are also outside the direct-assignment fix.

[[real-world-validation-follow-up]]
== Correctness and scale follow-up

The follow-up on 2026-09-10 UTC (2026-09-09 locally) addresses the next failures
observed while using the tool:

* `ask --json --explain` now emits valid JSON without a human strategy header.
* Implementation-selection questions can follow a bounded set of direct callers
  above retrieved operations. Ripgrep's choice between parallel and single-threaded
  search now reaches `run`. This is a navigation heuristic, not proof that a
  function contains the relevant branch. Exact names still take precedence.
* Explicit usage questions prefer retrieved documentation. Matching code symbols
  no longer crowd Flask's logging guide out of a mixed top-ten window. A document
  URI's repository name is no longer mistaken for a symbol-name match, and weak
  prose relationships need query overlap before promoting a code neighbor.
* Python and TypeScript named nested definitions own their call sites. Classes
  retain initialization calls and connect to members through `Contains`, without
  inheriting calls from method bodies. Unindexed anonymous callbacks remain
  conservatively attributed to the enclosing symbol. `understand` backlinks now
  label their relationship types, including parallel relationships.
* Missing `cargo audit` is reported as unavailable. Other audit failures preserve
  the actual diagnostic instead of claiming that every failure found vulnerabilities.
* Ignore rules treat dots literally. The old `.vs/` rule also excluded `vs/`,
  silently omitting VS Code's main source tree. Regression cases cover Windows
  and slash-separated paths while retaining the actual editor-directory exclusion.
* A freshness classification and its receipt share one content observation,
  removing a redundant full-tree read and keeping their evidence consistent.
  Equal-sized edits and timestamp-preserving rewrites still use content checks.
* Python and TypeScript reuse one source hash per parser input. Previously,
  symbol metadata reopened and hashed the complete file for every symbol.
  VS Code's 8.5 MB `test-checker.ts` fixture alone has 6,815 symbols, causing
  approximately 58 GB of repeated file reads. Reuse also keeps the metadata
  hash tied to the actual parsed buffer when it differs from disk.

The larger checkout is https://github.com/microsoft/vscode[VS Code], with 18,732
tracked files at Git commit `a0a429cd4ac624c0add568597f00b052c225ae56`.
The initial scale trial indexed only 3,555 code files / 38,640 symbols in 207.31 s
because of the ignore bug. Its warm lookup median was 10.24 s, and the central
`src/vs/base/common/lifecycle.ts` definition was absent. These failed results are
retained; they are not a successful large-repository baseline.

`DisposableStore` has several real definitions in this checkout. The corrected
scale workflow checks that the expected source definition is among the explicit
candidates, then pins its anchor for the question and MCP lookup. It does not
count an ambiguous name as unique or compare two missing anchors as a success.

With discovery fixed, the full checkout reports 11,937 code files / 173,664
symbols and 208,068 stored contracts. Cold `gen` took 493.46 s before hash reuse
and 143.62 s afterward, with the same contract count and 186,981 linked internal
calls. The final run passes all 44 required checks across the four repositories
and all three usage-routing observations. This is a single-machine comparison
with uncontrolled cache and background load, not a guaranteed speedup.

Large-project read startup remains the next performance target. The first outline
after generation took 60.51 s; subsequent exact-name lookups had a 12.83 s median,
the pinned question took 19.05 s, and fresh-process MCP lookup took 14.47 s.
The outline is explicitly truncated. These measurements validate bounded
navigation on this checkout, not complete call resolution or instant monorepo
responses. Further work should profile source verification and read-index loading
before introducing persistent caching or changing freshness guarantees.

The final small-project rerun passes all 37 required checks and all three new
usage-routing observations. Each implementation question reaches its expected
source; Flask logging, Express installation, and ripgrep search-mode usage reach
documentation. No upstream files remain modified.

The updated Flask simple export was also used in the browser: dispatch shows

structural relationships leaves the callable neighborhood intact; `/` focuses
search and the page opens dark. This does not certify browser performance on the
entire VS Code graph.

[[real-world-validation-reproduce]]
== Reproduce

Clone the upstream repositories into clean sibling directories named `flask`,
`express`, and `ripgrep`, and check out the commits above. Then run:

[source,shell]
----
python scripts/test-real-world-workflows.py --root <checkouts> --aden-bin <aden-executable> --output <report.json>
----

The JSON report retains binary version and hash, platform, upstream commits,
wall-clock timings, raw CLI and MCP receipts, every check, and exported-view paths.
Required mechanical and established implementation-query failures exit nonzero.
New usage probes remain explicitly recorded observations. Temporary index state
and HTML remain beside the report for inspection.

For the optional VS Code scale workflow, append:

[source,shell]
----
--large-repo <vscode-checkout> --large-symbol DisposableStore --large-source src/vs/base/common/lifecycle.ts
----
