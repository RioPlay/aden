= Aden: From Legacy Docs to S-Tier Context in Minutes

== What Is Aden?

Aden is a **context compiler** — not a documentation generator.

It turns any codebase into a **traversable, token-dense knowledge graph** where every function, module, and decision is a node, and every relationship is a typed, resolvable edge. AI agents (and humans) can then query this graph with natural language, locate symbols instantly, and understand impact before touching code.

== Why Aden?

Every codebase eventually becomes too large to fit in a single mind. Aden solves this by making your project's structure machine-readable:

- **Never guess** what breaks when you refactor — `aden ask "What depends on X?"`
- **Never read stale docs** — contracts are derived from source, not typed by hand
- **Never lose context** between discrete tool windows — everything is assembled into a single AsciiDoc artifact
- **Never leak internal architecture** — contracts are private build artifacts by default

== Quick Start: Zero → S-Tier in 60 Seconds

[source,bash]
----
# 1. Initialize a project (scaffolds .agent/ templates, .adenignore, etc.)
aden init

# 2. Generate contracts from your source code
aden gen src/lib.rs

# 3. Check that every reference resolves (知识 graph integrity)
aden check .

# 4. Ask questions in natural language
aden ask "How does the error handling work?"

# 5. See what breaks if you change a symbol
aden ask --from parse_module "What depends on me?"

# 6. Find the exact line where a symbol is defined
aden locate parse_module

# 7. Detect drift between code and contracts
aden heal --scan .

# 8. Run all local CI gates before committing
aden ci-check .
----

== Command Reference

|===
|Command |When to Use

|`aden init` |First time in any repository. Scaffolds `.agent/`, `.adenignore`, security manifest.
|`aden gen <path>` |After adding or modifying source files. Creates/updates `.adoc` contracts.
|`aden check <path>` |Before committing. Validates all `<<refs>>` and graph integrity.
|`aden ask <question>` |When you need architectural reasoning or impact analysis.
|`aden locate <symbol>` |When you know the name but not the file or line.
|`aden graph --depth N <symbol>` |To visualize dependency chains.
|`aden heal --scan <path>` |To detect contract drift (StaleHash, MissingContract, etc.).
|`aden ci-check <path>` |To run all local gates (check, heal, test, secrets) in one shot.
|`aden doctor <path>` |To audit your environment: tool versions, repo health, signing keys.
|`aden search <query>` |Full-text semantic search across all contracts.
|===

== Security: Private by Default

Aden assumes **contracts are build artifacts**, not source code.

- `contracts/` and `.aden/` are added to `.gitignore` automatically by `aden init`
- Contracts contain source paths and signatures — never commit them
- Pre-commit hooks scan for secrets (keys, tokens, env files)
- `ProfileMode = Internal` is the default; public redaction requires explicit opt-in
- If a contract ever leaks, treat it as a repo security event

== Architecture

|===
|Crate |Responsibility

|aden-core |Schema: Document, Block, Edge, Table, Symbol, ProfileConfig
|aden-parse |Language routers: Rust (tree-sitter), Python, PowerShell
|aden-emit |Deterministic AsciiDoc emitter for all node types
|aden-graph |Referential integrity: DiGraph, cycle detection, typed edges
|aden-asm |Context assembly: BFS traversal, token budgeting, assembly output
|aden-index |Semantic full-text search (tf-idf) over the graph
|aden-heal |Self-healing engine: drift detection, patch proposals, health scoring
|aden-propose |Patch generation, stub generation, proposal lifecycle
|aden-lsp |Language Server Protocol for `.adoc`/`.aden` files
|aden-py |PyO3 Python bindings for programmatic access
|===
