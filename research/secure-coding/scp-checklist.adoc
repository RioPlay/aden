[[scp-checklist]]
= OWASP Secure Coding Practices — Checklist Categories

Source: OWASP Secure Coding Practices Quick Reference Guide (technology-agnostic
secure-coding controls). Each category lists representative checklist items and
links to the weaknesses (<<cwe-top25>>) it mitigates.

[[scp-input-validation]]
== Input Validation
- Conduct all input validation on a trusted system (server side, not client side).
- Validate all data from untrusted sources; validate range, length, and type.
- Prefer allow-lists over deny-lists.

Mitigates <<cwe-89>>, <<cwe-79>>, <<cwe-22>>, and the general weakness
CWE-20 (improper input validation).

[[scp-output-encoding]]
== Output Encoding
- Conduct all output encoding on a trusted system.
- Contextually output-encode all data returned to the client.
- Sanitize output bound for SQL, XML, LDAP, and OS commands.

Mitigates <<cwe-79>>, <<cwe-78>>.

[[scp-error-handling]]
== Error Handling and Logging
- Do not disclose sensitive information in error responses.
- Log input-validation failures and authentication attempts.
- Do not store sensitive information in logs.

Mitigates <<cwe-200>>.

[[scp-memory-management]]
== Memory Management
- Check that a buffer is as large as specified before writing.
- Properly free allocated memory upon completion.
- Overwrite sensitive data in memory before release.

Mitigates <<cwe-787>>, <<cwe-125>>, <<cwe-416>>.

[[scp-file-management]]
== File Management
- Require authentication before allowing a file upload.
- Validate uploaded files by checking file headers, not just extension.
- Turn off execution privileges on upload directories.

Mitigates <<cwe-22>>, <<cwe-434>> (unrestricted file upload).

[[scp-data-protection]]
== Data Protection
- Store sensitive information securely; minimize what is retained.
- Never hard-code secrets in source.
- Encrypt sensitive data at rest and in transit.

Mitigates <<cwe-200>>, <<cwe-798>>.

[[scp-general-coding]]
== General Coding Practices
- Use tested, approved managed code rather than new unmanaged code.
- Do not pass user-supplied data to any dynamic execution function.
- Review third-party code and libraries; use bounds-checked deserializers.
- Bound resource use with timeouts and size/recursion limits.

Mitigates <<cwe-502>>, <<cwe-400>>, <<cwe-352>>, <<cwe-94>> (code injection).
