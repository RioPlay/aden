[[owasp-a05]]
== A05:2025 — Injection
Injection flaws arise when untrusted data reaches a query, command, or template
(SQL, NoSQL, OS command, template injection, ORM misuse). Detection is best by
source-code review plus automated fuzzing of all inputs (params, headers, URL,
cookies, JSON, XML).

Remediation: never concatenate user input into queries; use parameterized
queries; apply <<scp-input-validation>> and <<scp-output-encoding>>.

Maps to weaknesses <<cwe-89>>, <<cwe-78>>, <<cwe-79>>.

[[owasp-defense-in-depth]]
== Defense-in-Depth Note
Input validation (<<scp-input-validation>>) is a defense-in-depth layer, not the
primary control for XSS/SQLi — output encoding and parameterized queries are.
Combine layers: allow-list inputs, parameterize queries, encode output.
