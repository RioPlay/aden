== HIGH SEVERITY

=== [HIGH-1] Git argument confusion in `cmd_review_since`
**File:** `crates/aden-cli/src/main.rs:1359` +
**CWE:** 78 (OS Command Injection by Argument Confusion)

[source,rust]
----
let output = std::process::Command::new("git")
    .args(["diff", "--name-only", since])  // <1>
    .current_dir(path)
    .output()?;
----
<1> `since` is a raw user-supplied string from `--since <value>`.

**Impact:** Git options can appear anywhere on the command line. If `since` is crafted as `--output=/tmp/pwned` or `--exec=malware`, Git will execute it before parsing the remaining positional arguments.

**Recommended fix:** Pass `--` before `since` to terminate option parsing:
[source,rust]
----
.args(["diff", "--name-only", "--", since])
----

**Fix Applied:** `--` terminator added before `since` in both affected call sites: `cmd_review_since` at `main.rs:1359` and `cmd_heal_scan_since` at `main.rs:1454`. The `cargo test` invocation at `:1702` is hardcoded and accepts no user input.

[source,rust]
----
.args(["diff", "--name-only", "--", since])  // Options terminated
----

=== [HIGH-2] PowerShell path resolution not confined to trusted root
**File:** `crates/aden-parse/src/powershell.rs:63-104` +
**CWE:** 73 (External Control of File Name or Path)

[source,rust]
----
let script_path = std::env::current_exe()
    .ok()
    .and_then(|exe| exe.parent().map(|p| p.join("Export-AST.ps1")))
    .unwrap_or_else(|| Path::new("tools/ps-adapter/Export-AST.ps1").to_path_buf());
----

**Impact:** `current_exe()` on Unix resolves to `/proc/self/exe`, which is trustworthy, but the fallback `tools/ps-adapter/Export-AST.ps1` resolves relative to CWD. An attacker who controls the working directory can plant a malicious PowerShell script.

**Fix Applied:** Removed CWD fallback. Script is resolved only from the binary directory with `.filter(|p| p.is_file())`, and fails hard if the script is missing.

[source,rust]
----
let script_path = std::env::current_exe()
    .ok()
    .and_then(|exe| exe.parent().map(|p| p.join("Export-AST.ps1")))
    .filter(|p| p.is_file())
    .ok_or_else(|| Error::Io(
        "Export-AST.ps1 not found next to aden binary.".to_string()
    ))?;
----

== MEDIUM SEVERITY

=== [MED-1] Directory scan silently truncates after 5,000 files
**File:** `crates/aden-parse/src/lib.rs:64` +
**CWE:** 770 (Allocation of Resources Without Limits) — inverse: hard cap causes data loss

[source,rust]
----
const MAX_FILES_SCANNED: usize = 5_000;
----

**Impact:** Running `aden gen .` on a repository with >5,000 source files (e.g., Linux kernel has 63,000+ files) silently truncates at file 5,000. No warning is emitted; contracts are silently incomplete.

**Fix Applied:** Emits a `WARNING` to stderr when the 5,000-file limit is reached, so users know contracts are incomplete.

=== [MED-2] Large files silently skipped at 1 MB
**File:** `crates/aden-parse/src/lib.rs:65`

[source,rust]
----
const MAX_FILE_SIZE: u64 = 1024 * 1024; // 1 MB
----

**Impact:** Any file >1MB is skipped with zero feedback. Legal `.c` files in the Linux kernel exceed this (e.g., `rtw8852c_table.c` at 1.8MB).

**Fix Applied:** Emits a `WARNING` with the file path and size when a file exceeds the 1 MiB scan limit.

=== [MED-3] Symlinks are followed during directory traversal
**File:** `crates/aden-parse/src/lib.rs:72`, `crates/aden-graph/src/graph.rs:160` +
**CWE:** 59 (Improper Link Resolution Before File Access)

`std::fs::read_dir()` and `std::fs::metadata()` follow symlinks by default. A malicious symlink in the repo (e.g., `contracts/secret -> /etc/shadow`) would be read during contract generation.

**Fix Applied:** Symlinks are now skipped during directory traversal in `aden-parse`, `aden-graph`, and `aden-heal` (`entry.file_type().map(|ft| ft.is_symlink()).unwrap_or(false)`).

=== [MED-4] Secret scan regex patterns compiled per-file
**File:** `crates/aden-cli/src/main.rs:1681-1714`

[source,rust]
----
for pat in &patterns {
    if let Ok(re) = regex::Regex::new(pat) {  // <1>
        if re.is_match(&text) { ... }
    }
}
----
<1> Re-compiled on every file scanned.

**Impact:** The regex patterns (`AKIA[0-9A-Z]{16}`, `-----BEGIN ... PRIVATE KEY-----`) are anchored and unlikely to backtrack, but there is no rate limit on how many matches can be found. A 1MB file could, in theory, cause a ReDoS if patterns are ever made more complex.

**Fix Applied:** Replaced per-file compilation with a `std::sync::OnceLock<Vec<Regex>>` that compiles all patterns once on first use.

== LOW SEVERITY & INFORMATIONAL

=== [LOW-1] Session log lacks atomic write
**File:** `crates/aden-cli/src/main.rs:1195-1226`

**Impact:** Read → modify → write cycle on `session.adoc` is non-atomic. Two concurrent agents could corrupt the file.

**Fix Applied:** Session log now uses atomic temp+rename: write to `<session.adoc>.tmp`, then `fs::rename` to target path. Conflicting agents will see the later write.

=== [LOW-2] Multiple `unwrap_or_default()` on strings swallow errors silently
**Files:** `router.rs:81`, `generic.rs:133`, `c_resolver.rs:46`, `main.rs:948`, etc.

**Impact:** When file names contain invalid UTF-8, `to_string_lossy()` replaces bad bytes with `U+FFFD`. This can produce incorrect anchors in contracts.

**Fix Applied:** Documented: aden requires UTF-8 file paths. Operating on non-UTF-8 paths will produce lossy replacements. This constraint is acceptable for the target ecosystems.

=== [LOW-3] Unsigned nanosecond timestamp underflow
**File:** `crates/aden-cli/src/main.rs:1891`

[source,rust]
----
SystemTime::now().duration_since(UNIX_EPOCH).unwrap().as_nanos()
----

**Impact:** `unwrap()` panics if system clock is before epoch (extremely rare, but possible on VMs with clock skew).

**Fix Applied:** Replaced `unwrap()` with `unwrap_or_default()` on `duration_since(UNIX_EPOCH)`. Pre-epoch clocks return 0 instead of panicking.

=== [LOW-4] No crash isolation in MCP server
**File:** `crates/aden-mcp/src/main.rs`

**Impact:** If the MCP server panics (e.g., from a deserialization bug), it kills the entire process. No per-request isolation exists.

**Fix Applied:** Wrapped the server event loop in `std::panic::catch_unwind` in `aden-mcp/src/main.rs`. A panic in a request handler is caught, a message is written to stderr, and the process exits gracefully instead of aborting.

== Additional Fixes Discovered During Remediation

=== [MED-5] Symlinks followed in `aden-heal` scanner
**File:** `crates/aden-heal/src/scanner.rs:241`, `:259` +
**CWE:** 59

The heal scanner's `collect_source_files` and `collect_contract_files` followed symlinks, bypassing the hardening added to `aden-parse`.

**Fix Applied:** Added symlink check before traversing directories in `aden-heal/src/scanner.rs:246` and `:264`.

=== [HIGH-1b] Git argument confusion in `cmd_heal_scan_since`
**File:** `crates/aden-cli/src/main.rs:1428` +
**CWE:** 78

`cmd_heal_scan_since` had the identical vulnerability to `cmd_review_since` — `since` was passed without `--` to `git diff`.

**Fix Applied:** `--` terminator added at `main.rs:1454`.

=== [EXTRA] Absolute source paths leaked in emitted contracts
**File:** All parse resolvers (`crates/aden-parse/src/*/`) and `crates/aden-cli/src/main.rs` +
**Impact:** Contracts emitted by `aden gen` stored absolute paths in `:source_file:` attributes, leaking usernames and directory structure if contracts were ever exposed.

**Fix Applied:** Added `sanitize_source_file()` in `aden-cli/src/main.rs:636` that strips the current working directory prefix before emission. Both `cmd_gen` and `cmd_watch` use it. Generated contracts now contain relative paths only (e.g., `crates/aden-cli/src/main.rs`).

=== [HIGH-3] LSP temp file vulnerable to symlink hijacking (TOCTOU)
**File:** `crates/aden-lsp/src/main.rs:172` +
**CWE:** 59 / CWE-362

`publish_diagnostics()` wrote to a fixed filename `aden-lsp-temp.adoc` in the system temp directory. An attacker could pre-create a symlink at that path pointing to any file (e.g., `/etc/passwd`). When the LSP wrote document content, it would follow the symlink and overwrite the target.

**Fix Applied:** Replaced fixed filename with a unique path per call (`aden-lsp-{pid}-{nanos}.adoc`) and used `OpenOptions::new().create_new(true)` to atomically fail if the path already exists (symlink or otherwise).

=== [MED-6] LSP `goto_definition` / `hover` could navigate outside workspace
**File:** `crates/aden-lsp/src/main.rs:112`, `:139` +
**CWE:** 73

`goto_definition` and `hover` used `node.source_path` directly to construct file URLs. If a contract contained an absolute path outside the workspace (e.g., `/etc/passwd`), the LSP client would offer to navigate there.

**Fix Applied:** Added `is_in_workspace()` check in `aden-lsp/src/main.rs:96` using `canonicalize()` + `starts_with(root)` before returning any file URI.

=== [MED-7] `aden-index` followed symlinks during indexing
**File:** `crates/aden-index/src/lib.rs:203` +
**CWE:** 59

The inverted-index scanner traversed into symlinked directories, bypassing the hardening in `aden-parse` and `aden-graph`.

**Fix Applied:** Added symlink check before directory recursion in `aden-index/src/lib.rs:207`.

=== [LOW-5] LSP diagnostics rebuild graph on every keystroke (DoS)
**File:** `crates/aden-lsp/src/main.rs:112`, `:139`, `:177` +
**CWE:** 770

`goto_definition`, `hover`, and `publish_diagnostics` each call `AdenGraph::build_from_directory()` independently. On large repos, a rapid series of hover requests can consume 100% CPU for extended periods.

**Fix Applied:** `publish_diagnostics` now builds the graph once per pass and reuses it for both ref validation and include checks. Full graph caching across requests is deferred to a future architectural pass.

== New Command Security Review

During implementation of `aden new`, `aden kickoff`, and `aden workflow`, three path-traversal vectors were identified and remediated:

=== [MED-NEW-1] `cmd_new` directory escape via project `name`
**File:** `crates/aden-cli/src/main.rs:278` +
**CWE:** 22 (Improper Limitation of a Pathname)

`name` is joined directly to `parent`: `parent.join(name)`. If `name` is `../../../etc`, the project directory escapes the intended parent. This could overwrite arbitrary directories.

**Fix Applied:** Added `validate_name()` helper at `main.rs:276` which rejects any `name` containing `/`, `\\`, `..`, or `../`.

=== [MED-NEW-2] `cmd_kickoff` file overwrite via `name`
**File:** `crates/aden-cli/src/main.rs:445` +
**CWE:** 22 (Improper Limitation of a Pathname)

`format!("kickoff-{}.adoc", name)` is used as a filename. If `name` is `../../etc/passwd`, the file is written outside the repository.

**Fix Applied:** Reused `validate_name()` at `main.rs:441`.

=== [MED-NEW-3] `cmd_workflow` file read/write via `--from` and `--out`
**File:** `crates/aden-cli/src/main.rs:539,604` +
**CWE:** 22 (Improper Limitation of a Pathname)

`--from` and `--out` user strings are joined with `repo`. A value of `../../etc/passwd` could read or write arbitrary files.

**Fix Applied:** Added `safe_relative()` helper at `main.rs:508` which rejects any path string containing `..`.

== OWASP Top 10 Coding Vulnerability Scanner

A new static analysis gate (`owasp audit`) was added to `aden ci-check` and exposed as the standalone `aden audit` command. It scans source files across Rust, Python, Go, TypeScript/JavaScript, PHP, Java, and C/C++ for OWASP Top 10 coding patterns.

=== Architecture
- Uses `Regex` patterns compiled once via `std::sync::OnceLock` (ReDoS-safe)
- Skips `.agent/` and `docs/` directories (documentation containing example strings)
- Skips comment lines and string literals to reduce false positives
- Skips lines containing `Regex::new` (pattern definitions themselves)
- Language-tagged rules avoid cross-language false matches
- Supports `--format text|json|adoc`
- `--strict` mode treats critical/high findings as CI-blocking

=== Known Limitations
- SAST regex-based; cannot track data flow across functions
- May miss context-sensitive issues (e.g., `eval` used with a completely static string)
- Does not analyze compiled bytecode or bytecode-equivalent AST
