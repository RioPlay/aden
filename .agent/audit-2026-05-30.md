## [HIGH] Unsafe string slice on character-counted index in markdown heading parser
- **category:** panic-risk   **confidence:** 0.99
- **location:** crates/aden-parse/src/markdown.rs:79
- **why:** level is counted as characters (e.g., emoji = 1 char), but line[level..] indexes by byte position. If heading contains multi-byte UTF-8 characters before the text, this panics with 'byte index X is not a char boundary'. Example: '#😀 Title' where emoji is 4 bytes but counted as 1 char.
- **evidence:** /home/unknown/Projects/aden/crates/aden-parse/src/markdown.rs:77-79 — the code counts `#` characters with `line.chars().take_while(...).count()` but then indexes the string as bytes with `line[level..]`. If the markdown heading is `#😀 Title`, level=1 (character count) but `line[1..]` panics because byte 1 is in the middle of the 4-byte emoji 😀 (U+1F60F). No bounds check, no char-boundary validation, no documentation of the limitation.
- **action:** Replace byte-index slicing with character-based slicing: change `line[level..].trim()` to `line.chars().skip(level).collect::<String>().trim()`. This safely skips the first `level` characters before trimming, avoiding UTF-8 boundary panics. Add a regression test with emoji/multi-byte characters in markdown headings.
