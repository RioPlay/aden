[[glossary]]
= Project Glossary

Core terminology used throughout aden. See `docs/architecture.adoc` and
`docs/security-model.adoc` for fuller treatment.

[cols="1,3"]
|===
|Term |Definition

|Anchor
|A stable, addressable definition in the graph, written `[[id]]` in source/docs
and addressed as an `aden://…` URI (e.g.
`aden://module/aden/aden---module-aden-cli-query.rs-cmd_asm.adoc#code_block_3`).
Anchors are what you feed to `asm`/`query`; you copy the one a tool returns rather
than hand-typing it.

|Reference
|A pointer to an anchor, written `<<id>>`. A reference whose target anchor is
missing produces a `BrokenReference` drift event.

|Contract
|The generated, machine-readable description of a symbol or document section
(signature, relationships, provenance). Contracts are build artifacts and are
gitignored.

|Drift
|Divergence between the source code and the recorded graph/contracts — e.g. a
changed signature (`StaleHash`/`SignatureMismatch`) or a `BrokenReference`.
Detected by `check`; repaired by `heal`.

|Heal
|The operation (`aden heal`) that detects drift and rewrites contracts to match
current source, keeping the graph in sync with the code.

|Knowledge Graph
|The compiled representation of a project: anchors as nodes, references and
extracted relationships as typed edges. Held in-memory (petgraph) and persisted
to the Store.

|Store
|The persistent, materialized view of the graph, backed by the `fjall`
embedded LSM key-value store (crate `aden-store`). Read tools query it directly.

|Assembly (`asm`)
|Building a focused context prompt by running a breadth-first traversal (BFS)
from an anchor, bounded by a token budget (~4 bytes/token heuristic, hard cap).
Emits the relevant neighborhood instead of whole files.

|Constitution / Policy
|The project's enforceable rules (crate `aden-policy`) — constraints and gates
applied during `check`/`ci-check`.

|Edge types
|The typed relationships between anchors. Real edge types include: `Uses`,
`UsedBy`, `Implements`, `Tests`, `Documents`, `Calls`, `Invokes`, `Requires`,
`Mutates`, `IsA`, `PartOf`, `RelatesTo`, `SimilarTo`, `Causes`, `Explains`,
`Supersedes`, and `Amends`. (The illustrative `Supports`/`Contradicts`/`Owns`
edges referenced in `docs/use-cases.adoc` are aspirational and do not exist.)
|===
